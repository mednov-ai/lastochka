# Пользователи и безопасность — локальная реализация

30.10.2026 реализовано `refine-users-and-security-layout`. Раздел пользователей показывает компактные строки с именем, логином и ролью, статусом и адресным действием. Строки с длинными значениями растут и переносятся; свой аккаунт выделен пояснением. В безопасности форма пароля и ключи расположены рядом на достаточной ширине и последовательно на узкой; действия подтверждения и ключи находятся вместе. Ссылка «Вернуться к расписанию» удалена из добровольной формы, переход сохранён в навигации. Новые стили ограничены этими разделами; общая обязательная форма и существующие правила доступа сохранены.

## Проверки

- Просмотрены снимки на 320 и 1440 CSS px, в том числе с длинными тестовыми именем и логином; обычный список и безопасность сопоставлены с исходными снимками из обращения. Стандартные строки на 1280/1440 измерены не выше 96 CSS px; длинная строка может быть выше. Две панели проверены на 1280/1440, последовательная компоновка на 320–430. Прокрутка при нескольких ключах или коротком окне остаётся естественной.
- 40 браузерных проверок Chromium/WebKit × ru-RU/en-US на тестовых ответах прошли, включая ширины 320, 375, 430, 768, 1000, 1280, 1440, увеличение текста до 200%, окно высотой 650, контуры фокуса, размеры интерактивных элементов и отсутствие горизонтального переполнения. Ещё 4 проверки повторной отправки создания пользователя прошли в тех же контекстах. Проверены пустой список ключей и список из двух, статусы паролей, длинные данные, загрузка/ошибка/пагинация, сохранение ввода, ограниченная сессия, соседние разделы и главная. Контраст выборки текста, границ полей и индикатора фокуса соответствует порогам 4,5:1 и 3:1.
- На отдельном временном PostgreSQL и локальном backend 8/8 браузерных проверок прошли в Chromium/WebKit на 375/1440: создание, обязательная и добровольная смена, адресный сброс, отзыв прежней сессии, no-JS запрет. В Chromium виртуальный ключ создан до сброса и проверен после смены. Дополнительный локальный Chromium-сценарий прошёл повторное подтверждение, создание двух виртуальных ключей, переименование, проверку и отзыв одного с блокировкой отзыва последнего. Реальные физические ключи не использовались.
- `npm run typecheck`, `npm run build` и `check:ui-language` прошли; проверка Prettier изменённых frontend-файлов прошла. Строгая проверка OpenSpec прошла. Скриншоты и журналы находятся в игнорируемом `artifacts/users-security/`; снимки настоящих цепочек с тестовыми аккаунтами — в `artifacts/password-lifecycle-baseline/` с префиксом `users-security-`.
- Созданные для этой проверки процессы, временный PostgreSQL-контейнер и его хранилище удалены; существующие сервисы не менялись. Рабочие аккаунты, ключи и данные площадки не использовались.

Изменения локальные; сервер, production, физические устройства, скринридеры и удалённый CI отдельно не проверялись. API и схема базы не изменялись. Фактическая тестовая площадка по последнему отчёту остаётся backend/frontend 0.16.2/V18; поставка и архивирование этого изменения не выполнялись.
