# Эксплуатация заявок и уведомлений

Заявки хранятся в PostgreSQL и видны допущенным ADMIN независимо от транспорта. Сохранение заявки не резервирует место и не подтверждает её доставку. В разделе «Заявки» общие флажки управляют только новыми заявками; пустой набор каналов допустим. До настройки выбранный по умолчанию Telegram остаётся в ожидании и не мешает приёму.

## Браузерные уведомления

Нужны защищённый origin и поддерживаемый браузер. Оператор хранит пару VAPID и контактный HTTPS URL только в защищённом env-файле приложения (`PUSH_VAPID_PUBLIC_KEY`, `PUSH_VAPID_PRIVATE_KEY`, `PUSH_VAPID_SUBJECT`). Для пустой конфигурации `python3 scripts/configure-browser-push.py /путь/к/закрытому.env https://адрес-студии/` создаёт пару P-256 и атомарно сохраняет файл с правами 600; существующую пару скрипт не заменяет и секреты не выводит. Нужен системный Python с `cryptography`. Не размещать закрытый ключ в Git, сообщениях, отчётах или клиентском коде. Перед изменением env сохранить защищённую резервную копию; compose должен передавать все три значения backend.

После применения конфигурации каждый ADMIN открывает «Заявки» → «Уведомления о заявках», включает общий канал и отдельно нажимает «Подключить это устройство», разрешив уведомления браузеру. Для отказанного разрешения его нужно изменить в настройках браузера/ОС. Уведомление содержит только номер, а переход открывает защищённый кабинет. Статус «принято сервисом» не означает показ или прочтение. Режимы экономии энергии, ОС и поддержка браузера могут задерживать доставку; отдельная физическая приёмка устройств остаётся необходимой.

Кнопка отключения отзывает только подписку текущего ADMIN/устройства. Другое устройство нужно отключить на нём; утрата допуска, смена версии доступа, восстановление с новой generation или замена публичного VAPID-ключа делают старые подписки недействительными. После смены ключа администраторы подключают устройства заново. Рабочий ключ не менять без необходимости: прежние подписки и неотправленные задания перестают быть действительными. Старые задания не рассылаются повторно после restore.

Отдельные состояния в карточке заявки показывают выбранные каналы и сводку push по устройствам. Временные сбои повторяются с ограничением попыток и времени, ответ 404/410 отключает подписку. Неисправность одного устройства не останавливает Telegram или другие устройства. При неясном результате возможен повтор одного уведомления с тем же номером; новая заявка при этом не создаётся.

## Telegram

Бот и чат сейчас не подключаются. При отдельной настройке оператор задаёт токен и chat ID в защищённой конфигурации, не передавая их посетителю. При переносе чата виден безопасный статус, настройку вручную обновляет оператор. Настоящую доставку проверять только отдельной синтетической заявкой в специально настроенный тестовый чат; имитатор не является подтверждением реальной доставки.

## Восстановление и совместимость

Новые сборки требуют V18 и маркеры `ADMIN_ENQUIRIES_V1`, `PASSWORD_LIFECYCLE_V1`, `RECURRING_GROUPS_V1`, `ENQUIRY_MULTICHANNEL_V1`. Старые backend и frontend с V15 не являются проверенным откатом после заявок без имени или возраста ребёнка. Не накатывать прежний dump поверх актуальных данных. Поставка выполняется по прямому поручению; для текущего изменения поручена тестовая площадка. Перед поставкой проверять резервную копию восстановлением, миграцию на приватной копии, допустимые образы и соседние сервисы; disaster restore требует новой внешней ADMIN_ACCESS_GENERATION и повторного подключения браузерных устройств. Если совместимый вариант отката не подготовлен и не проверен, при сбое сохранить базу и устранять проблему совместимой сборкой.
