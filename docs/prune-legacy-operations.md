# Эксплуатация после удаления старой модели

Версия 0.9.0 поддерживает схему V12. Действующий продукт — ADMIN/гостевые заявки,
расписание, Telegram-очередь и платёжные черновики. Вход/пароли/ключи и внутренний
principal accounts.email сохраняются. Старые API отвечают410, почтовый подпуть404.

## Перед обновлением V11

Проверить обе метки концепции и schema.min/schema.max, manifest и runtime JAR/SSR.
Новая миграция не меняет V1–V11 и отказывается удалять непустые старые таблицы
или непредусмотренные FK. Не обходить отказ CASCADE или автоматической очисткой.
Требуются приватные backup БД/env/config/maildir, проверка pg_restore в отдельной
БД и сверка отпечатков действующих данных, а также извлечение почтового архива
со сверкой имён/SHA256. На малом сервере не запускать вторую JVM параллельно.

Обновляется согласованная пара образов через короткое обслуживание только Lastochka,
со старым приложением/worker в остановленном состоянии. Используется новая Compose
без SMTP/MailHog. Остальные env, origin/RP, пароли и access generation при обычном
обновлении не меняются. Проверить сессии/ключи, календарь/заявку/повтор/DRAFT,
health/readiness/liveness, старые адреса и соседние сайты. Не изменять общие TLS/ACME.

## Удаление MailHog

Только после приёмки приложения и проверенного backup выставляется checkpoint
acceptancePassed в приватном отчёте перехода. scripts/remove-owned-mail.py проверяет
владельца Compose-проекта каждого из трёх именованных почтовых контейнеров, потребителей
mail-volume/network и целостность архива. Он останавливает и удаляет только эти
контейнеры, их maildir volume и mail-сеть. Неиспользуемые образы удаляются без force;
общий Nginx image и образы с другими потребителями сохраняются. Общий prune/down -v
не используется. Проверки чужого владельца и общего ресурса есть в --self-test.

Операторский MailHog и его порты больше не существуют. Старые приватные конфигурации,
release-артефакты и backup остаются историей, а не штатной командой запуска. Не закрывать
чужие SSH-процессы: собственная инструкция туннеля18027 выводится из эксплуатации,
существующий пользовательский SSH-туннель может оставаться открытым без сервиса за ним.
Письма доступны только в приватном проверенном maildir.tar.gz, новый архивный UI не создаётся.

## Восстановление

0.8.0 имеет старую concept-метку, но не поддерживает V12: gate обязан его отклонять.
Откат разрешён только на подтверждённую schema-aware пару, сохраняющую текущие заявки,
очередь и DRAFT. Нельзя накладывать старый dump поверх новых данных. Disaster restore
выполняется изолированно с новой внешней ADMIN_ACCESS_GENERATION; до открытия доступа
проверяются marker, Flyway и административный допуск. Восстановление почтовой копии
для чтения не означает возвращение SMTP/публичного MailHog в эксплуатацию.
