## Постоянные правила

Правила языка закреплены в AGENTS.md и openspec/config.yaml. Повторяемые инструкции
frontend находятся в `frontend/app/ui/ui-texts.ts`; backend использует
`messages.properties`. Стандартные ограничения и успешная отправка форм сохранены.
Политика нового пароля остаётся 6–128 Unicode code points / L / Nd, вход старым
паролем не требует нового состава. Сырые браузерные/сетевые исключения не показываются.

`npm --prefix frontend run check:ui-language` проверяет пользовательские TS/TSX-строки,
каталоги, JSX/атрибуты, собственный HTML/JS/CSS почтового просмотра и backend-тексты.
AST-анализ следует по переменным, импортам, ветвям, картам подписей и сообщениям
состояния. Новые raw `<form>` вне RussianForm также блокируются: иначе возврат
браузерной проверки на английском обошёл бы каталог. Проверка выполняется перед штатной сборкой, в CI и при упаковке приложения,
frontend и публичной почты, а также при генерации почтового UI.

Словарь и точные исключения — `scripts/ui-language/policy.json`. Допустимы MailHog
только в его публичном HTML и Telegram только в контактном блоке главной.
Причина и область обязательны; разрешение названия не разрешает английскую фразу
рядом. API-поля, URL, адреса, пользовательские имена и письмо не переводятся.
Кириллические технические термины проверяются по явным словоформам.

## Добавление текста

1. Написать понятную русскую формулировку и переиспользовать каталог для повторов.
2. Запустить проверку языка. При ошибке исправить указанный текст; не разрешать
   весь файл/каталог и не добавлять старые нарушения как разрешённую базу.
3. Новое необходимое название добавить в словарь с точным контекстом и причиной.
4. Проверить смысл: латиница не является единственным признаком непонятного текста.
5. Проверить затронутую форму/ошибку при en-US и ru-RU, доступность, мобильную ширину.

## Границы анализа

Динамические источники перечислены в policy.json. API/опубликованный контент,
пользовательские данные и тексты писем проверяются сценариями и правилами источника;
статический анализ не доказывает язык произвольных runtime-данных. Для Kotlin
анализируются собственные строковые сообщения, непосредственные MessageResponse
и email-формулировки; это не полный межпроцедурный анализ JVM. OpenAPI-описания,
SQL, сторонние библиотеки и внутренние коды не являются пользовательскими текстами.
Окна ОС, браузерный календарь/автозаполнение и системная валидация без JS не переводятся.
Собственные статические пояснения без JS остаются русскими.

## Дополнения по результатам реализации

В WebKit обнаружен и исправлен возврат фокуса после клика по ссылке: окно теперь
запоминает фактический открывший элемент, а не только document.activeElement.
Это относится и к кнопкам записи через общий компонент ссылки.

Вспомогательный скрипт локального auth-стенда теперь явно закрепляет порты прокси
и включает SMTP-обработчик. Перезапуск из тестового процесса больше не наследует
его PORT и флаг отключённых фоновых обработчиков. Проверка перезапуска в security
выбирает именно этот стенд при localhost:5177.

Проверки pattern/minLength/дополнительного max в russian-feedback.spec.ts используют
временные атрибуты реальных элементов для проверки общего помощника. Новые ограничения
в продукт не добавлялись. В штатных формах проверены обязательность, email,
московская верхняя граница даты рождения, вместимость/шаг и ограничение длины ввода.
Превышение maxLength браузер предотвращает ещё при вводе; отсутствие native-ошибки
в этом случае не считается пропуском защиты.

Доставка новых писем проверена только через SMTP/MailHog. Сохранённые письма не
переводятся. Реальная доставка и физические ключи доступа не принимались этим изменением.
Для упаковки локально необходимы Node 24 и установленные frontend devDependencies;
серверу эти инструменты не требуются. Прямой нестандартный вызов компилятора в обход
штатных команд не является защищённым путём сборки; CI и документированные команды
сборки/упаковки используют обязательную проверку.

После приёмки собственные native-процессы и контейнеры двух выделенных
испытательных стендов остановлены; volumes и результаты сохранены. Основной
пользовательский MailHog, SSH-туннель и серверные сервисы этим изменением не управлялись.
Локальный этап:20/20 задач и строгая проверка пройдены. После серверной поставки
итог изменения —26/26 задач; OpenSpec архивирован 23.10.2026, требования синхронизированы.
