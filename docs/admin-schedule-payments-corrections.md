# Индивидуальные исправления занятий и кабинет — 30.10.2026

Изменение `improve-admin-schedule-payments-and-pagination` выполнено локально, 17/17.
Локальная версия разрешает индивидуальные исправления неотменённого занятия
после начала. Для опубликованных и закрытых занятий сохраняется общий серверный
черновик и отдельная публикация с проверкой версии и пересечений; существующие
заявки и их снимки не пересчитываются. Изменение отдельного вхождения сохраняет
связь с серией и исключение. Отменённое занятие доступно для просмотра и истории;
отмена и изменение приёма после начала не разрешены. При изменении времени
предпросмотр предупреждает о возможном изменении доступности новых заявок.

Пагинация пользователей компактнее с целями от 44 CSS px. Диалог оплаты
расположен в центре, его крестик не смещается при наведении и клавиатурном
фокусе. Сохранены поля, маска телефона и сообщение об отсутствии провайдера.

## Решение и ограничения

У занятия один общий серверный черновик. При одновременной публикации первая
команда применяет и удаляет его, вторая получает 409; отдельного сохранённого
черновика второго администратора система не создаёт. По решению пользователя
ввод второго администратора остаётся в открытой форме: он принимает актуальную
основу и может сохранить новый общий черновик. Пока форма открыта, несохранённые
изменения защищены подтверждением закрытия; это не отдельное серверное хранение.

Старый браузерный комплект серий отдельно не запущен: его исходный локальный
тестовый контейнер отсутствовал. Граница текущей недели и повторная проверка
подтверждены серверными тестами с управляемыми часами; прежний отчёт
`recurring-current-week-and-plan-table.md` содержит браузерные проверки серии в
разных часовых поясах. Физические устройства, скринридеры, CI и фактический
откат отдельно не проверялись.

На момент локальных проверок площадка была frontend 0.16.4/backend 0.16.2/V18.
Последующая разрешённая поставка 0.17.0 описана в
`docs/deployment/2026-10-30-admin-schedule-payments-corrections.md`. Старый backend
не поддерживает исправление прошлого; при откате сначала возвращают совместимый
frontend, а уже опубликованные исправления не отменяются автоматически.
