`0.23.0-enquiry-directions-test-20261113`, схема **V29**. Изменение OpenSpec

## Что изменилось для посетителя и администратора

- Форма заявки: имя, телефон, обязательная возрастная категория из справочника (плашки
  3–5, 6–7, 8–9, 10–13, 14+), необязательное «Кто будет заниматься», комментарий.
  Переключатель «Для ребёнка / Для себя» и числовой возраст убраны.
- «Удобное занятие — необязательно» свёрнуто; внутри ближайшие занятия за 14 дней только
  выбранной категории, по 5 с «Показать ещё». Выбор не перезагружает страницу и не
  сбрасывает прокрутку; без JavaScript фильтр работает через CSS `:has()`.
- Карточка афиши предвыбирает занятие и категорию; «Оставить заявку» в строке категории
  афиши — только категорию (`/enquiry?direction=…`).
- Заявка хранит снимок категории; Telegram-сообщение и админка показывают категорию и
  имя занимающегося. Контракт заявки v3; v2 по-прежнему принимается.

## Уведомления администратору — не работают на test

Read-only проверка окружения test-backend: `LASTOCHKA_WORKERS_ENABLED=false`, переменные
`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `PUSH_VAPID_*` не заданы; подписок push 0; в
настройках включён Telegram, push выключен. Флаг workers управляет только отправкой
Telegram и push. Значит, заявки сохраняются и задания ставятся, но **ни одно уведомление
не отправляется**.

Дополнительно 14.11.2026: сеть `lastochka-test_default` объявлена `internal`, единственный
выход наружу — CONNECT-прокси Альфа-Банка, пропускающий только `alfa.rbsuat.com`.
`PushSender` (Apache HttpClient) ходит напрямую и сам проверяет адрес службы push,
`TelegramSender` использует `java.net.http`. Поэтому даже с ключами VAPID и
`LASTOCHKA_WORKERS_ENABLED=true` push и Telegram с test наружу не выйдут: нужен
отдельный разрешённый выход (решение пользователя) и, для прокси, правка отправителей. Для приёмки нужны бот и чат от пользователя, ключи VAPID, включение
workers и подписка устройства ADMIN.
