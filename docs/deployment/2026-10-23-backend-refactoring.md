## Откат без замены данных

Установить только BACKEND_IMAGE=lastochka-backend:0.6.1 в рабочей application env;
frontend0.6.1 и public mail UI1.0.1 оставить. Затем:

```sh
docker compose -p lastochka-preview \
  --env-file /opt/lastochka/shared/.env.preview \
  --env-file /opt/lastochka/mailhog-public/shared/public.env \
  -f /opt/lastochka/releases/mailhog-websocket-20261023/compose.preview.yaml \
  -f /opt/lastochka/mailhog-public/current/compose.mailhog-public.yaml \
  up -d --no-deps --wait backend
```

Тем же вызовом пересоздать собственный proxy:
`up -d --no-deps --force-recreate proxy`. Проверить readiness, вход,
календарь и WSS/SMTP. Прежний image сохранён. V9, новые данные, volumes,
ключи/generation и письма не откатывать; dump поверх рабочей БД не восстанавливать.
Обратная совместимость проверена локально в сценарии старый→новый→старый;
живой откат сервера не выполнялся и не потребовался. Для отдельного disaster
restore действует требование новой внешней attendance generation из runbook.
