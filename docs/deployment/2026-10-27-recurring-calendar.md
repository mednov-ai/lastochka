# Календарь и регулярные группы — поставка и архивирование 27.10.2026

По прямому поручению пользователя тестовая площадка
https://play-and-say.ru/lastochka/ обновлена до **backend/frontend0.13.0, PostgreSQL V15**.
Все 14 завершённых активных OpenSpec-изменений синхронизированы и архивированы.
Активных изменений не осталось. Production-поставки сайта не было.

## Что поставлено

Компактный административный календарь с рабочей шириной до1000px и масштабом60px
за час. Исходный диапазон08:00–22:00 МСК расширяется для внеурочных занятий;
мобильный экран показывает список дня. Создание, перенос и изменение длительности
через сетку сначала открывают редактор, затем требуют явного сохранения.
Постоянные группы не содержат списка детей. Недельные серии имеют конечный диапазон,
сохранённый серверный черновик, полный план с конфликтами и атомарную публикацию.
Одиночные изменения сохраняют принадлежность и становятся исключениями.

[Поведение и локальная приёмка](../recurring-groups-calendar.md),
[эксплуатация и ограничения отката](../recurring-groups-operations.md).

## Резервная копия и миграция

Исходное состояние подтверждено реальным SSH: frontend0.12.1/backend0.11.0/V14,
три ADMIN. Проверены Nginx, Docker/Compose, память, место и соседние страницы.
Резервная копия: `/opt/lastochka/backups/pre-0.13.0-20261027T165612Z/`.
Приватные dump/env/config/state имеют права700/600; секреты не выведены в отчёт.

Dump восстановлен в отдельную серверную БД; 14 контрольных отпечатков совпали.
Новая Linux/amd64-сборка проверена на приватной локальной восстановленной копии:
readiness прошла, V14→V15 применилась, прежние столбцы/данные всех14 таблиц
совпали. Использовалась новая внешняя generation и выключенные фоновые отправки.
Этот вариант выбран, чтобы не запускать второй JVM на общем сервере с ограниченной
свободной памятью. Локальные копия, контейнеры, их одноразовый том и сеть после
проверки удалены; исходная серверная копия сохранена.

Сверялись accounts, user_credentials, user_entities, landing_content,
studio_settings, studio_sessions, session_edit_drafts, audit_events,
idempotency_records, enrollment_requests, enquiry_replays, telegram_outbox,
payment_requests и concept_state. V15 только добавляет таблицы групп, серий,
связей и истории; старые миграции не переписаны.

## Публичная приёмка

По настоящему HTTPS прошли **313 проверок**, включая **288 прежних ресурсов**,
и отдельно **56 браузерных регрессионных сценариев** публичного расписания и
показа пароля в Chromium/WebKit ×en-US/ru-RU ×375/1440.

- Две полные цепочки групп/серий в Chromium1440/ru-RU и WebKit375/en-US,
  зона браузера America/Los_Angeles: создание группы, пн/ср/пт,12 дат,
  сохранение/повторное открытие черновика из календаря и публикация.
- Удаление сред оставляет8 дат с исходными ID. Прежний запрос без полей группы
  сохраняет связь, создаёт разовое исключение и инвалидирует старый план;
  следующий предпросмотр сохраняет это исключение. История читается с сервера.
- На поставленном backend конфликт последней даты полного плана дал409;
  сравнение публичного набора до/после подтвердило отсутствие частичной публикации.
- Настоящая заявка без JavaScript с выбранным конкретным занятием принята.
  Проверены доступность `/#schedule`,404 прежнего `/schedule`, отказ гостевого
  доступа к ADMIN API, геометрия и200% текста, перенос без неявной записи.
- ADMIN-сессия, созданная до rollout, осталась FULL. Прогретая вкладка перешла
  через «Пользователи» обратно в расписание; после reload открыт новый календарь.
  Все288 прежних ресурсов доступны.

Первый вспомогательный прогон нажал создание серии после сообщения об успешной
записи группы, пока завершалось обновление данных панели. В окончательном прогоне
сценарий ждёт завершения сохранения по доступности кнопки; изменение продукта для
этого не потребовалось. Лишняя проверочная группа включена в адресную очистку.

Снимки заполненной сетки, мобильного черновика и результата no-JS просмотрены.
Локальная предшествующая приёмка включала63 backend-теста,24 целевых и104
регрессионных browser-сценария,24 проверки публичной части localhost,24 адаптивных
снимка, миграцию/restore и фактический старый frontend0.12.1 с новым backend.

## Откат

Подготовлен и загружен **lastochka-frontend:0.12.1-schema15**: прежний интерфейс
с явной совместимостью V15, используемый только с backend0.13.0.
Прежний UI/старые одиночные команды с новым backend проверены; это откат оформления,
он не удаляет новые данные. Фактическое переключение сервера назад не выполнялось.

Для отката оформления адресно заменить только FRONTEND_IMAGE на этот тег,
выполнить штатный Compose `up -d --no-deps --wait frontend` с сохранёнными
project/env/compose и пересоздать только собственный proxy для DNS. Проверить
readiness/HTTPS/данные. Для возврата нового UI использовать lastochka-frontend:0.13.0.

**backend0.11.0 после появления серий небезопасен.** Для исправления или отката
backend обязательны оба механизма PASSWORD_LIFECYCLE_V1 и RECURRING_GROUPS_V1.
Старый dump не накладывать поверх новых заявок; аварийное восстановление требует
отдельной БД и новой внешней ADMIN_ACCESS_GENERATION.
