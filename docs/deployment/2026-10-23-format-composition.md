# Карточки форматов — поставка frontend 0.4.1

23.10.2026 по поручению пользователя на <https://play-and-say.ru/lastochka/>
развёрнут frontend **0.4.1**, backend остаётся **0.3.0**. Исправление
`fix-format-card-image-composition` теперь доступно на тестовом сервере.

В «Мини-группе» используется полноценная иллюстрация из презентации. Все три
формата показывают исходные кадры пропорционально, без обрезания голов рамкой,
scroll-маской или hover/focus zoom. Последовательное движение карточек и отклик
рамки/подложки/CTA сохранены. Описание кода и локальных проверок:
[композиция форматов](../format-card-composition.md).

## Публичная приёмка

На публичном HTTPS без Basic Auth прошли **4 browser-сценария**:

- Все три карточки: ширины 320/375/390/430/768/1024/1280/1440/1920, высоты
  700/1000 — 54 карточки и 234 положения областей голов в реально видимой рамке.
  Сохранены и просмотрены мобильный/desktop-снимки; лицо и макушка не срезаются.
- Scroll 0/25/50/75/100% и обратные 50% на 375/390/1440, hover/уход указателя,
  клавиатурный фокус без геометрического скачка и обрезки.
- No-JS, reduced-motion и coarse-pointer: те же полные кадры, регистрация
  открывается первым касанием/кликом, прямой адрес регистрации без JS работает.
- Непрерывный wheel-scroll вперёд/назад: Chromium 156.0.8078.4, 60 Hz,
  CPU ×4, прогретые изображения/шрифты, viewport 375×900 и 1440×900.

| Viewport | Кадров | p95 | Интервалы >50 ms | Long tasks | Layout events | Максимальный вызов сцены |

| 375×900 | 230 | 16.8 ms | 0% | 0 | 0 | 0.705 ms |
| 1440×900 | 175 | 16.8 ms | 0% | 0 | 0 | 0.762 ms |

Бюджет выполнен; это эмуляция Chromium, не приёмка физического телефона.

Отдельный операторский browser-сценарий: **20 проверок** прошли. Публичные байты
WebP совпадают с проверенным ресурсом; все шесть CTA гостя показывают регистрацию,
просмотр расписания открыт. Существующий client4 входит с прежним паролем без
WebAuthn; FULL CTA ведёт к расписанию, Link/кабинет/reload и route data работают,
admin API родителю и личный API гостю закрыты. Cookie Secure/HttpOnly/Path=/lastochka
сохранена; собственная успешная сессия приёмки завершена logout. Аккаунты,
дети, занятия, заявки и письма для проверки не создавались.

Вкладка, открытая **до** обновления, получила девять старых JS/CSS и выполнила
schedule.data → 200. Доказательство сохранено в browser-first-run.json.
Первый операторский прогон затем ожидал кабинет после входа, хотя сохранённое
намерение корректно вернуло пользователя к расписанию. Ожидание теста исправлено;
повторный прогон принял безопасный возврат и завершил остальные 20 проверок.
Приложение для этого не менялось, успешное доказательство старой вкладки сохранено.

## Сохранность и откат

До rollout, сразу после него и после приёмки совпали отпечатки accounts, children,
studio_sessions, bookings, user_credentials, user_entities и landing_content.
Все семь аккаунтов, роли и прежние пароли сохранены; на момент проверки детей,
занятий, записей и ключей было 0. Seed, смена паролей и миграции не запускались.

После приёмки сохранён готовый dump:
`/opt/lastochka/backups/lastochka/ready-for-testing-frontend-0.4.1-20261023.dump`
(600, 38 449 байт); непустой архив и pg_restore --list проверены. Новое
восстановление в отдельную БД в этом frontend-релизе не выполнялось.

Play&Say `/` и RepairDevice `/repair_demo/` отвечают 200 и совпали по SHA256
с новым снимком перед поставкой. Nginx vhost/snippet не изменены, nginx -t
успешен, certbot.timer активен. Prefix/query redirect 308, TLS 1.2 и прежний
запрет TLS 1.3 проверены. Служебные URL/порты снаружи закрыты. После поставки
доступно около 523 MiB RAM; собственный временный контейнер проверки удалён.

Rollback: изменить только FRONTEND_IMAGE на `lastochka-frontend:0.4.0`, выполнить
Compose с рабочей env: `up -d --no-deps --wait frontend`, затем
`up -d --no-deps --force-recreate proxy`; проверить health/соседей. Не выполнять
откат БД/down -v и не удалять assets volume. Предыдущий image возвращает известную
обрезку мини-группы. Откат не понадобился.
