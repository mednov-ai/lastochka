# Движение лендинга и путь записи — frontend 0.4.0

Поставка начата 19 октября и завершена **20.10.2026, Europe/Moscow**.
На <https://play-and-say.ru/lastochka/> работает frontend **0.4.0**,
backend остаётся **0.3.0**. Change: `refine-landing-motion-and-booking`.

## Результат

Исправлен реальный сбой клиентских переходов: SSR runtime принимал `.data`
запросы React Router за статические файлы и отвечал 404. Теперь они доходят
до маршрутизатора, неизвестные страницы/файлы сохраняют 404, JS не подменяется HTML.
Проверки выполняли Link-клики, историю, reload и переход из вкладки, открытой
до обновления. Прямой GET расписания сам по себе этот дефект не выявлял.

Все шесть кнопок записи (header, hero, три формата, контакты) открывают гостю
модальную регистрацию с переключением на вход. После подтверждения email
и парольного входа открывается расписание; WebAuthn доброволен. Выбранное занятие
сохраняется через безопасный next/хранилище с TTL 30 минут. Истёкшее/недоступное
хранилище в сценарии регистрации возвращает к расписанию; внешние next отклоняются.
Заявка требует отдельного выбора ребёнка и действия родителя, затем одобрения.
Для полноценной сессии CTA ведёт сразу к расписанию; ссылки просмотра расписания
публичны. Без JS у кнопки действующий адрес регистрации.

Три сцены используют обратимый локальный прогресс: раскрытие рамки и фон hero,
прорисовка непрерывного пути через три тезиса, последовательное раскрытие форматов.
Scroll и hover меняют разные слои. Изображения плавно приближаются при наведении,
карточки/ссылки реагируют рамкой, подложкой и стрелкой; клавиатура получает фокус.
Портрет сохраняет исходные 1122×1402 и запас сверху, hover не обрезает лицо.
Структура/текст доступны без JS и с reduced-motion. Подробности:
[storyboard](../scroll-storyboard.md).

## Проверки

- 17 целевых локальных production browser-сценариев прошли: CTA/регистрация,
  MailHog/подтверждение в новой вкладке/password-only/явная PENDING-заявка,
  selected-session/история кабинета, TTL/unsafe/blocked storage, модальные формы,
  контент без пересборки, SSR/no-JS/reduced-motion/keyboard, сцены/hover/портрет,
  reload/resize/очистка listeners и бюджет. После обнаруженного конфликта
  старого синтетического слота тест выбирает свободное время; пять сценариев
  пути записи повторно прошли целиком.
- Typecheck, Prettier и production build прошли. Повторные экспорт OpenAPI
  и генерация TypeScript побайтово совпали с прежними артефактами. Backend-код,
  контракт и миграции не менялись; прежние 23 backend integration tests описаны
  в [отчёте 0.3.0](2026-10-19-public-access.md), заново здесь не запускались.
- Проверены пять состояний каждой сцены на 375/1440, обратный ход, hover/focus,
  портрет 375/390/1280/1440/1728/1920 при высотах 700/1000; снимки просмотрены.
- Linux/amd64 image запущен локально без исходников: SSR и readyz UP/version 0.4.0.
- Публичная HTTPS-приёмка: **43 проверки** без Basic Auth. Восемь старых JS/CSS
  assets доступны; вкладка до rollout выполняет schedule.data → 200. Все CTA
  проверены на 375/1440; отдельный временный PARENT проходит настоящее SMTP-письмо
  MailHog, новую вкладку подтверждения и парольный вход в расписание без passkey.
  Проверены кабинет/история/reload, отсутствие автоматической записи, запрет admin
  API родителю и личного API гостю, Secure/HttpOnly/Path=/lastochka cookie.

  регистрация первым касанием без hover, закрытие диалога и отсутствие overflow.
  Это эмуляция touch в Chromium, не приёмка физического телефона.

## Откат и материалы

Для отката изменить только FRONTEND_IMAGE на `lastochka-frontend:0.3.0`
в защищённой рабочей env. Из каталога release выполнить Compose с этой env:
`up -d --no-deps --wait frontend`, затем `up -d --no-deps --force-recreate proxy`.
Проверить readyz/лендинг/соседей. Не выполнять down -v, не очищать public-assets
volume и не откатывать БД. Старый image 0.3.0 возвращает известную ошибку `.data`;
при необходимости повторно выпустить исправленный frontend. Откат не понадобился.

Игнорируемые материалы: `artifacts/landing-refinement/` (локальные состояния,
портреты, trace/video/budget), `artifacts/server-deploy/0.4.0/` (публичная приёмка,
сохранность, screenshots и `motion/` с публичными trace/video/budget),
`artifacts/frontend-release-0.4.0/` (archive/manifest). Операторские журналы —
`runtime-data/`. Секреты и исходный info не входят в Git. Исторические отчёты
0.2.0/0.3.0 сохранены. RuSender, платежи, редактор и физические passkey остаются
отдельными этапами.
