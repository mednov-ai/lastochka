# Исправление доставки ВКонтакте на test

25 ноября 2026 года на test выпущены backend и frontend `0.27.1-vk-delivery-test-20261124` из `8ddf9377293237afc10b95159c6bedf997ff30f2`, схема V34 прежняя. Запущен ретранслятор `vk-egress`, обработчик включён. **Канал ВКонтакте пока выключен: ключ не введён, доставка не принята.** Production не выпускался.

Дополнение compose и конфигурация ретранслятора взяты из последующих коммитов `develop`, образы при этом не менялись. Выполнено под root по прямой отмашке владельца. Сценарий и журналы — `runtime-data/vk-delivery-test-20261124/`.

## Найдено при выпуске

- JVM на test направляет HTTPS в прокси, который пропускает только банк. Запросы ВКонтакте шли бы в него мимо ретранслятора. Добавлен `-Dhttp.nonProxyHosts=api.vk.com`, остальные параметры JVM прежние.
- DNS 1.1.1.1 с сервера недоступен. Ретранслятор использует 77.88.8.8 и 8.8.8.8.
- Первая проба показала чужой SNI принятым: Java возобновила сессию прежнего запроса с именем `api.vk.com`. В чистой JVM и через openssl соединение отклоняется.

## Проверено

- Копия V34 `pre-vk-delivery-20261125T050231Z-2b58aa8a` (SHA-256 `a3056399d9e8aca7b84bb9fb229adb3657482e68f66d36e616df913e56433d68`) восстановлена отдельно, отпечатки 33 таблиц совпали. После замены они не изменились.
- Девять остальных контейнеров, включая весь production и PostgreSQL, сохранили идентификатор, образ и время старта; vhost прежний. Различия compose — только образы, параметр JVM и ретранслятор.
- Из сети backend с его параметрами JVM `api.vk.com` отвечает ошибкой 15 (нет ключа) с действительным сертификатом. Отклонены другой сайт, прямые адреса 8.8.8.8 и ВКонтакте (с хоста открыты), чужой SNI, соединение без SNI и без TLS. Портов ретранслятор не публикует.
- VAPID пуст, очереди ВКонтакте и push пусты до и после включения. Две прежние записи Telegram в ожидании не изменились, обработчика для них нет.
- В журнале backend два предупреждения SpringDoc, ошибок и ключей нет. Доступно 593 МБ памяти, ретранслятор занимает 2 из 32 МБ, backend — 383 из 480 МБ.
- 555 из 555 ресурсов совпали. TLS 1.2 принят, TLS 1.3 отклонён. Главная, расписание и страница входа проверены в Chromium и WebKit на 1440 и 375 px без ошибок страницы.

## Не проверено

Настоящая доставка, заявка через форму, вход администратора, операции банка после выпуска, откат и физические устройства. Открытая задача 4.3 архивного изменения уведомлений ВКонтакте остаётся.

## Возврат

Вернуть `VK_TEST_WORKERS_ENABLED=false`, пересоздать backend и остановить `vk-egress`. Прежние образы 0.26.0 и 0.27.0 совместимы с V34; конфигурация до выпуска — `root-release.env.before` в каталоге выпуска на сервере. Базу поверх test не восстанавливать.
