# Адрес и секретный ключ ВКонтакте в тестовом кабинете

28 ноября на test выпущены backend и frontend `0.27.17-vk-display-test-20261128`. Исходники взяты из рабочего каталога `develop` на `1aa4850` вместе с ранее опубликованными локальными правками. Публичный healthcheck вернул новую версию. Схема базы V35.

В реальной сессии ADMIN после нажатия «Показать адрес и секретный ключ для ВКонтакте» появились реквизиты для «Ласточка-тест». Ввод строки подтверждения для этого действия не потребовался.

На HTTPS стенда в Chromium и WebKit при 1440 и 375 CSS px проверены первое подключение, просмотр уже подготовленной пары после перезагрузки и копирование обоих значений. Для этих сценариев использованы подставные ответы API и проверяемый буфер обмена. Иконки копирования примыкают справа к полям, каждая область нажатия не меньше 44 × 44 CSS px. [Компьютер](evidence/vk-display-20261128/desktop.png) · [Мобильный экран](evidence/vk-display-20261128/mobile.png)

12 интеграционных тестов ВКонтакте прошли на изолированной БД. OpenAPI совпал с экспортом работающего backend. Перед заменой сервисов свежая копия тестовой базы восстановлена отдельно, отпечатки 33 таблиц совпали. Сохранность 598 прежних ресурсов и состояния 10 других контейнеров проверены. TLS 1.2 принят, TLS 1.3 отклонён.

Для выпуска с разрешения владельца удалены две жёсткие ссылки на архив образа `weekly-test-20261119/backend.tar.gz` на VPS. Локальная копия сверена по SHA-256. Освобождено 468 МиБ. На момент выпуска прежний маршрут ещё принимал события. Результат переключения приведён ниже.

## Сохранение после повторного просмотра

В 20:10 МСК на test опубликован backend `0.27.18-vk-setup-test-20261128`. Прежний лимит в пять операций за 15 минут суммировал показы реквизитов и попытки сохранить строку. Он убран для административной настройки Callback. После выпуска в реальном кабинете ADMIN шесть раз подряд открыт один и тот же адрес, затем сохранена строка подтверждения. Публичный запрос подтверждения для тестового сообщества получил HTTP 200 с точным ожидаемым телом. Интеграционный набор ВКонтакте прошёл 12 из 12 проверок. Перед заменой backend свежая резервная копия test восстановлена отдельно, отпечатки 33 таблиц совпали. Сохранены 602 статических ресурса и состояние 11 остальных контейнеров.

## Приёмка доставки и отключение прежнего адреса на test

В 20:16 МСК входящее сообщение на адрес из кабинета подтвердило беседу «Ласточка-тест». В 20:18:27 ВКонтакте принял проверочное сообщение, в 20:18:34 в кабинете включена отправка. В 20:18:59 через публичную форму создана контрольная заявка №10. В карточке появился статус «Принято ВКонтакте». Владелец подтвердил получение отдельного сообщения «Новая заявка №10» со ссылкой на карточку. [Карточка заявки №10](evidence/vk-display-20261128/enquiry-10-delivery.jpg).

После приёмки из конфигурации Nginx тестового сайта удалён маршрут, который передавал запросы со старого публичного адреса в приложение. Конфигурация прошла проверку и применена через reload. Внешние запросы подтверждения по TLS 1.2 вернули 404 для старого адреса и прямого пути прежнего обработчика. Адрес из кабинета вернул 200 и точную строку подтверждения сообщества. Для последующих выкладок на test проверять эти ответы вместо успешного подтверждения на прежнем адресе.
