# Выпуск обновлённого сайта на test — 10 ноября 2026

На `https://test.lastochka-gym.ru/` опубликованы backend/frontend `0.20.0-test-20261110` и схема V24. Выпуск production не выполнялся. Доступ root для резервной копии, проверки восстановления, миграции и замены двух test-сервисов отдельно подтверждён пользователем. Обслуживание production и его базы в разрешение не входило.

## Резервная копия и миграция

- Тестовая база была V21; перед операцией проверялись среда, идентификатор и отдельная роль `lastochka_migrator`. Создана копия `/opt/lastochka/backups/test/pre-redesign-20261110T174305Z-c986fdac0be1/test-v21.dump`, SHA-256 `581f0618472222e49c2dc180c78697600f96801b7c8385559d4374e1bad8d2a3`. До этого ошибка: версия test проверялась операторским доступом вместо предусмотренной роли чтения; об этом сообщено пользователю. Production БД не затрагивалась.
- Копия целиком восстановлена в отдельную локальную временную БД. На ней успешно проверены переход V21→V24 через Flyway 12.4.0 с ролью мигратора, запуск нового backend с runtime-ролью и число записей по всем таблицам. После миграции изменилось только число записей истории Flyway: +3. Миграция test затем выполнена тем же пакетом SQL; обновлены test-манифест и конфигурация выпуска. Прежние файлы манифеста и конфигурации сохранены рядом с резервной копией.
- Первая попытка запуска мигратора остановилась до изменений: контрольная сумма архива SQL была вычислена до закрытия архива. Готовые файлы на компьютере и VPS совпали; сумма исправлена, повторная проверка и миграция прошли.
- Для 33 таблиц число строк test после выпуска сравнено с восстановленной копией: +3 строки в истории миграций, +1 анонимная веб-сессия и +1 атрибут сессии после браузерных проверок. Число строк прочих таблиц совпало. Это сравнение не является полным поэлементным сравнением содержимого; V24 намеренно обновляет ряд исходных текстов главной страницы.

## Сервисы и проверки

- На VPS загружены и сверены образы backend `sha256:896ce3391583621c7784b719ebd5c58313f3b5d7be8c932faf6f1a03f71f7975`, frontend `sha256:2f852d44cace68d1fdb73df602d7ac9a17d141d7a22e2771f1cce3753347b190`. Заменены только test backend/frontend. Внутренние адреса, на которые настроен test-прокси, сохранены; контейнер test PostgreSQL не перезапускался. Прежние образы сохранены. Старый backend не является безопасным автоматическим откатом после появления новых данных 14+.
- Все 55 файлов предыдущей сборки frontend проверены на test по SHA-256 через HTTPS. Два локальных последовательных прогона проверки старой вкладки прошли; первый предварительный прогон завершился тайм-аутом, причина не установлена. Существующую пользовательскую вкладку на сервере отдельно не проверяли.
- На реальном HTTPS с Playwright проверены главная и форма заявки на широком и узком экране, переключение недель, выбор формы для ребёнка и для себя, ссылка VK, открытие страницы входа и отсутствие горизонтального переполнения на ширине 390 px. На ближайших двух неделях опубликованных занятий нет, поэтому показывается пустое состояние. Саму отправку заявки, вход в настоящий кабинет и физические устройства не проверяли.
- Test `/` возвращает 200, старый путь `/lastochka/` — 308 к корню. После выпуска test и production отвечают с TLS 1.2 и отклоняют TLS 1.3; публичная страница production по-прежнему показывает заглушку. Конфигурацию, контейнеры и БД production в ходе выпуска не меняли. Содержимое production после ввода PIN не проверялось.
- Браузер при первом открытии запросил отсутствующий `/favicon.ico` и получил 404. Основные проверенные ресурсы загрузились; иконка вкладки остаётся небольшим открытым замечанием.
