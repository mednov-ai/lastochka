## База

Перед миграцией backend остановлен. Свежая копия `/opt/lastochka/backups/production/lastochka-production-20261126T104334Z-10e64589eaee9af6.dump` создана с правами `0600 root`. SHA-256 копии `6e0e55edf7535b408089a786a88002af4bc3af8ec2778c360abf7492629f1970`.

Копия восстановлена в отдельном PostgreSQL без доступа к рабочей сети. Миграции V21 → V34, включая Java-миграцию V28, прошли на копии и затем на рабочей базе одним пакетом. До миграции проверено отсутствие датированных занятий и старых шифротекстов Альфа-Банка. Отпечатки аккаунтов и оплат и идентификаторы заявок совпали. Права рабочей роли проверены готовностью приложения и чтением API. Контейнер и том PostgreSQL сохранены.

## Проверки

- Оба новых контейнера healthy. Идентификаторы и время запуска остальных десяти контейнеров совпали, включая test, прокси и PIN-gate.
- Снаружи видна заглушка. Закрытый API без PIN недоступен. После ввода действующего PIN открываются главная, форма заявки и страница кабинета, API расписания читает данные V34. API настроек VK без сессии ADMIN возвращает 401.
- На production и test принят TLS 1.2 и отклонён TLS 1.3. Контрольные суммы конфигураций обеих зон совпали.
- 55 из 55 файлов предыдущего frontend сохранены в архиве статических ресурсов и совпадают по SHA-256.
- На test ранее подтверждена автоматическая доставка синтетической заявки №4 в беседу VK. На основном сайте фоновые обработчики оставлены выключенными. Подключение рабочего VK, вход в реальную сессию ADMIN и отправка заявки на production отдельно не проверялись.

После V32 прежний backend V21 несовместим с новой схемой. При проблеме следует сохранить текущие данные и исправлять выпуск вперёд. Возврат к V21 возможен только через отдельное восстановление и согласованное переключение. Резервная копия не накатывается поверх рабочей базы.
