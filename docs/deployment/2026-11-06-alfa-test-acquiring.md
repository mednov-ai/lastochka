# Тестовый эквайринг Альфа-Банка — тестовая поставка 06.11.2026

## Обновление backend 0.19.2

На стенд поставлено исправление описания OpenAPI: запущенный backend отдаёт
корректные поля callback и write-only поля реквизитов. Действующие версии: backend
**0.19.2**, frontend **0.19.1**, PostgreSQL **V21**. Для V21 сделан свежий backup
`/opt/lastochka/backups/pre-alfa-openapi-20261106T175705Z-1ebfdc04/`; его
восстановили во временную БД и сравнили 27 контрольных таблиц. После обновления
и адресного удаления отдельного проверочного ADMIN все 27 таблиц совпали со
снимком; исходный `admin1` активен, фактический вход с его паролем не проверяли.

Сессия синтетического ADMIN, открытая до обновления, сохранилась; защищённые API
и выключенное состояние банковской настройки проверены через HTTPS. Доступны
474/474 файлов текущего общего каталога статических ресурсов, тестовая страница
возврата отвечает с no-store/no-referrer, неподключённый callback возвращает 404.
Проверены работающий JAR, неизменность остальных конфигураций и контейнеров,
соседних сайтов, read-only монтирований и выключенных банковских флагов. Frontend,
PostgreSQL и общий Nginx не перезапускались; proxy приложения пересоздан.
Реальное подключение к банку и фактический откат по-прежнему не проверялись.

## Предыдущая поставка 0.19.1

На тестовую площадку https://play-and-say.ru/lastochka/ поставлены backend и
frontend **0.19.1**, схема PostgreSQL **V21**. В «Безопасности» ADMIN доступна
форма тестовых реквизитов; оплаты разделены на активные и архивные таблицы.
Реальное подключение к банку, выпуск и отмена банковских заказов и callback на
стенде **выключены**: банк пока не подтвердил способ неразрушающей проверки
конкретного мерчанта, разрешения отмены, настройки подписи и хосты платёжной
формы. Настоящие банковские реквизиты и карты при приёмке не использовались.
Переход на production в эту поставку не входит.

## Резервирование и переход

- Исходная площадка: backend/frontend 0.18.0, схема V19, три ADMIN. Backup с
  конфигурацией и PostgreSQL dump: `/opt/lastochka/backups/pre-alfa-20261106T141426Z-9ef644a2/`.
  Снимок восстановлен в отдельную временную БД; все **23 контрольные таблицы**
  совпали. Контрольная учётная запись и сессия созданы после этого backup.
- Копия dump перенесена в закрытую локальную среду и сверена по SHA-256. Финальный
  Linux/amd64 backend применил V19→V21 на копии в изолированной сети; все **23/23**
  отпечатка совпали. Банковый контур и фоновые внешние работники были выключены,
  использовалась отдельная generation.
- Пара образов сверена с пакетом и release gate `ALFA_TEST_PAYMENTS_V1` и
  `STAFF_PERMISSIONS_V1`; работающие JAR и frontend SSR совпали со сборкой по
  SHA-256. Старый backend без новой модели не считается безопасным откатом на V21.
- PostgreSQL не перезапускался, время его запуска осталось
  `2026-10-19T13:14:38.540764642Z`. Общий Nginx проверен `nginx -t` и перечитал
  конфигурацию: в целевой snippet добавлены точные маршруты возврата и callback без
  записи query; остальные проверенные конфигурации и соседние сайты сохранены.

## Безопасность и приёмка

- Корневой CA Минцифры получен по проверенному HTTPS из официального источника.
  В отдельном Java `SSLContext` проверены TLS и имя тестового шлюза; независимая
  проверка со стенда также установила TLS и получила HTTP 403 на базовом адресе
  без передачи реквизитов. Это не доказывает доступ к API мерчанта. CA монтируется
  только backend для отдельного банковского клиента, системное доверие JVM не менялось.
- Мастер-ключ находится в отдельном защищённом серверном каталоге, копия — отдельно
  от backup БД на локальной машине в игнорируемой Git папке `alfa-payments/key-backup/`.
  На Linux проверено чтение ключа и CA под UID 10001 в монтировании read-only и отказ
  чтения ключа посторонним UID. Тесты на отдельной БД проверили ротацию,
  конкурентную запись, отказ и восстановление синтетического ключа; восстановление
  реального серверного ключа вместе с backup БД отдельно не проводилось.
- Через HTTPS с отдельной временной ADMIN-сессией проверены прежние защищённые API,
  сохранение сессии при обновлении, запрет изменяющей команды без CSRF и сохранение
  синтетических реквизитов как шифротекста. Ответы и проверенные журналы не
  содержали тестовых маркеров; кандидат остался `UNVERIFIED`, а попытка выпуска при
  выключенном TEST не создала банковский заказ. Созданные проверочные данные
  удалены адресно; банковские таблицы после очистки пусты, а **23/23** контрольных
  отпечатка и три исходных ADMIN сохранены.
- Публичная тестовая страница возврата отвечает по HTTPS; неподключённый callback
  отклоняется. Синтетический query-маркер отсутствовал в общих и контейнерных логах,
  для страницы возвращены политики `no-referrer` и `no-store`. Страница сама не
  подтверждает оплату. Все **440/440** ранее сохранённых ресурсов доступны по HTTPS.
- Локально прошли **131 backend-тест**, включая PostgreSQL, TLS, конкурентный выпуск,
  архивирование и HMAC; `architectureCheck`, генерация OpenAPI, typecheck,
  production-сборка и строгая проверка OpenSpec прошли. UI проверен также на
  подставных данных в Chromium/WebKit, в том числе возврат с поддельными параметрами.
- Финальный HTTPS UI проверен в Chromium/WebKit при ширине 375 и 1440 px; пустые
  активная и архивная таблицы запрашиваются отдельно, ADMIN видит пустую форму,
  проверочная сессия сохранилась. Ошибок JavaScript и переполнения не обнаружено;
  в каждом контексте был ожидаемый HTTP 401 `REAUTH_REQUIRED` при чтении ключей
  после истечения пятиминутного подтверждения пароля.

Реальные тестовые транзакции, подтверждение callback и лимитов мерчанта, удалённый
CI, физические устройства и фактический откат отдельно не проверялись. Изменение
OpenSpec остаётся активным с незавершёнными задачами и не архивируется. После этой поставки возник отдельный [инцидент локальной базы](../alfa-local-database-incident.md); последующее обновление backend 0.19.2 описано выше.

## Откат

Не возвращаться на backend 0.18.0 после V21 и не накладывать старый dump поверх
новых данных. При проблеме сначала оставить интеграцию отключённой и использовать
только проверенную совместимую пару с V21, `STAFF_PERMISSIONS_V1` и
`ALFA_TEST_PAYMENTS_V1`; если её нет, восстановить доступ исправленной версией
вперёд. Реальное переключение назад отдельно не выполнялось. Операционные
инструкции: [подключение](../alfa-test-operations.md) и
[ключи](../alfa-test-key-operations.md).
