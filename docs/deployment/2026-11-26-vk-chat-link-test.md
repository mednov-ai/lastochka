# Привязка беседы ВКонтакте по коду на test

26 ноября 2026 года на test выпущены backend и frontend `0.27.5-vk-chat-link-test-20261126`. Схема V34. Состав выпуска зафиксирован в `runtime-data/vk-link/` как ревизия `b209985fae34fc11596e44ac6b9852f51d1351e0` и два файла изменений. Вкладка «Заявки → Уведомления о заявках → ВКонтакте» поддерживает выбор из списка и одноразовый код. Код живёт 10 минут в памяти backend и сбрасывается при его перезапуске.

## Проверки

- Резервная копия V34 восстановлена в изолированной базе. Отпечатки 33 таблиц совпали. Новые контейнеры backend и frontend healthy, конфигурация production и остальные десять контейнеров сохранены.
- Подтверждение Callback API по HTTPS и отказ при событии без секрета проверены. Прежний внешний адрес Callback API теперь направлен в приложение. Временный диагностический обработчик остановлен, прямой публичный URL внутреннего маршрута отвечает 404. TLS 1.2 принят, TLS 1.3 отклонён.
- Gradle проверил модуль уведомлений и интеграцию VK. Chromium и WebKit с подставным API проверили список бесед, запуск привязки, ожидание и переход к тестовой отправке на ширинах 1440 и 375 px. TypeScript и проверка языка прошли.
- В реальной сессии ADMIN на test проверена выдача кода. ВКонтакте доставил событие с новым кодом, кабинет подтвердил «Ласточка-тест», VK принял тестовое сообщение из кабинета. Пользователь подтвердил получение тестового сообщения. После отдельного включения канала через публичную форму отправлена одна синтетическая заявка №4. Кабинет показал «Принято ВКонтакте», пользователь подтвердил появление отдельного уведомления №4 со ссылкой в «Ласточка-тест».

До выпуска прямая проба VK API доставила сообщение в «Ласточка-тест» в 13:08 МСК. После выпуска проверен полный сценарий через кабинет.
