# Исправление входа по PIN — 10 ноября 2026

Production возвращал 403 до проверки PIN, когда CSRF-токен открытой формы не
совпадал с общей cookie браузера. На форме генерировалось новое значение при
каждом открытии, поэтому другая вкладка или повторный запрос заглушки могли
сделать уже показанную форму недействительной. При воспроизведении в браузере
проверены корректный Origin, наличие cookie, несовпадение токенов и HTTP 403.

Gate теперь сохраняет действующий токен в корректной host-only cookie при
повторном открытии формы. Без cookie или с некорректным значением создаётся
новый случайный токен. Проверки Origin, CSRF, PIN, ограничение попыток и срок
cookie сохранены. Одновременные самые первые запросы без cookie всё ещё могут
получить разные токены; в таком случае нужно заново открыть заглушку.

По запросу владельца на исправление входа заменён только production gate на
`lastochka-site-gate:pin-csrf-20261110`, image ID
`sha256:17b8e1419901d7df809c924d9fa8796260efacfd7e5cb447299527d99a256fd4`.
При пересоздании gate прежние gate-сессии отозваны; секреты и состояние лимитов
сохранены. Production backend, frontend и proxy запущены с 9 ноября. Проверены
неизменные ID и время запуска production PostgreSQL и ID контейнеров test;
содержимое всех таблиц и резервных копий отдельно не сравнивалось. Данные и
схема БД не менялись операцией.

Проверки: 11 тестов gate; две вкладки на изолированном gate в Chromium desktop,
Chromium mobile и WebKit mobile; изолированный Nginx с закрытым и открытым
режимами, защитой маршрутов и проверкой сбоев; на production — две формы,
реальный PIN, защита прямого API, доступность test, TLS 1.2 и отказ TLS 1.3.
После установки реальный вход на production прошёл во встроенном браузере,
где ранее воспроизводился сбой. Физические устройства и вход администратора
отдельно не проверялись. Старые открытые формы могут требовать обновления.

До замены сохранена защищённая копия конфигурации образа
`/opt/lastochka/releases/pin-csrf-20261110/root-release.env.before`; прежний
образ `sha256:db72e4724fbeb69f67d3bf87fc3049945cbdbbb39a098955cb5c2c8c96a686e0`
остался на сервере. При ошибке скрипт выпуска восстанавливал конфигурацию и
пересоздавал только прежний gate; фактический откат не потребовался и отдельно
не выполнялся. Возврат выполняется оператором только после проверки режима и
прежнего образа, с сохранением закрытого vhost и без изменений БД и backup.
