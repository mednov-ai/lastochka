# Лента с ласточкой на test

24 ноября 2026 года на test обновлён frontend до `0.27.0-landing-ribbon-test-20261124`. Backend `0.26.0-vk-notifications-test-20261122` и схема V34 прежние, production не выпускался.

Источник — `develop` на `ba8f573a83426e9e45672e221ea846ef8a3e7046` и незакоммиченные правки frontend. Патч (SHA-256 `d27a41fa1884013f5afc78f87e4d8ef8d60bfe2bc5aeaade7ee09ffdc0af4e74`), новые файлы в каталоге `source`, сценарии и журналы находятся в `runtime-data/ribbon-test-20261124/`. Сборка на Node 24.22.2, образ `sha256:915e20512a08f9384746c94fcc8dfe2e996db850cfe1d71efb0dad29dae6a361`, `linux/amd64`.

## Место на сервере

Перед выпуском диск был занят на 98%, свободно 434 МБ, выпуск остановлен. По разрешению владельца удалены семь архивов прошлых выкладок из `/home/lastochka-agent` (513 МБ): копии есть локально, SHA-256 сверены перед удалением. После выпуска свободно 838 МБ (96% занято), доступно 387 МБ памяти. Затем по отдельному подтверждению владельца удалены остальные 12 архивов test из `/home/lastochka-agent`, включая загруженный архив этого выпуска; SHA-256 сверены. Каталоги, Docker и резервные копии не затронуты.

## Выпуск

Выполнен операторским сценарием под root по прямому указанию владельца. Сверены хост, test, V34, образы, Compose, том ресурсов и IP. Заменён только frontend. Сценарий подтвердил прежние идентификаторы, образы и время старта десяти остальных контейнеров и контрольную сумму vhost production.

## Проверено по HTTPS

- Версия в `/healthz` и `/readyz`, TLS 1.2 принят, TLS 1.3 отклонён, пять категорий и 14 интервалов, заявка, политика и вход — 200, API администратора без сессии — 401, production отвечает 200.
- 555 из 555 ресурсов прежних и новой сборок совпали по SHA-256.
- Chromium и WebKit на 320, 390 и 1440 px: лента, акценты, раскрытие всех блоков, отсутствие горизонтальной прокрутки и ошибок. Переход от времени к заявке с выбранным пожеланием. Уменьшенное движение и режим без JavaScript.
- [Снимки](evidence/landing-ribbon-test-20261124/).

В одном из шести первых заходов расписание не показалось: параллельно шла проверка 555 ресурсов. Причина не доказана; вероятна действующая граница ожидания 3,5 с. Следующие 30 заходов без нагрузки успешны, медиана появления расписания 3,0 с в Chromium и 3,8 с в WebKit.

Не проверены физические устройства, скринридеры, реальная отправка заявки, вход администратора и откат.

## Возврат

Прежний образ frontend `0.26.0-vk-notifications-test-20261122` совместим с текущими backend и V34. Прежняя конфигурация сохранена в каталоге выпуска на сервере.
