# Разграничение доступа сотрудников

06.11.2026 изменение `add-staff-permissions` реализовано локально, затем поставлено на тестовую площадку и архивировано; см. [отчёт поставки](deployment/2026-11-06-staff-permissions.md). Оно добавляет роль STAFF и индивидуальные права на просмотр и изменение расписания и черновиков оплат, а также независимый доступ к заявкам. ADMIN сохраняет полный доступ. API и проверка совместимости не допускают неизвестные права и старый backend без поддержки модели. Банковская интеграция и реальные платежи не реализованы.

Карта методов и дополнительных ограничений находится в [staff-permissions-route-map.md](staff-permissions-route-map.md), инструкции по назначению, миграции и откату — в [staff-permissions-operations.md](staff-permissions-operations.md).

## Локальная проверка

- PostgreSQL 17.6: исходный backend 0.17.1 создал синтетическую V18 с ADMIN. Отдельный dump восстановлен в другую базу; новая версия применила V19 через Flyway. Ранее открытая ADMIN-сессия и список пользователей сохранились. На этой восстановленной базе с новым backend старый frontend 0.17.0 проверен с ADMIN в четырёх разделах. Это проверка совместимости, а не одобренный откат.
- На другой синтетической V18 отдельно сверены прежние поля ADMIN, сессии, тестового ключа, заявки и оплаты до и после SQL V19; ограничения БД отклонили неизвестное право и неподдерживаемую роль. Миграция пустой базы Flyway до V19 также проверена. Данные с реального сервера не использовались.
- На изолированном PostgreSQL 32 сочетания пяти прав проверены HTTP-запросами, включая чтение и команды; проверены CSRF, немедленный отзыв, самостоятельный платёж и запрет привязки к заявке без доступа. Проверены конкурирующие изменения и защита последнего ADMIN, аудит и жизненный цикл временного пароля. Полный локальный набор: 106 backend-тестов без ошибок и `architectureCheck` без нарушений.
- Реальный локальный frontend с новым backend: создание STAFF, обязательная смена пароля, просмотр расписания, создание формы оплаты и отзыв права с сохранением ввода. Регистрация и проверка ключа STAFF проверены виртуальным устройством WebAuthn Chromium. Физический ключ не использовался.
- Браузерные проверки используют подставные ответы API; они охватывают управление правами, совместное действие из заявки, режим просмотра, отзыв с двумя вкладками, клавиатуру и размеры 320–1440 px и 200% текста. Прошли 24 сценария Chromium, включая соседние регрессии; расширенная подборка прав — 8 сценариев Chromium и 8 WebKit, включая завершение уже отправленной команды после отзыва.
- OpenAPI экспортирован штатным скриптом и клиентские типы сгенерированы из него. На Node 24 проверены typecheck и production build; проверка языка интерфейса прошла. Release gate прошёл положительные и отрицательные self-test, включая несовместимый старый backend. `openspec validate --all --strict`: 18 passed, 0 failed.

Реальная площадка и её резервная копия, production, удалённый CI, физические мобильные устройства и физический ключ отдельно не проверялись. Доставка browser push сотруднику не проверялась на реальном устройстве. Откат площадки не выполнялся. В npm audit осталась ранее известная высокая уязвимость зависимости; её эксплуатация для этого изменения не исследовалась.
