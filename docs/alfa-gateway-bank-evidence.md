# Альфа-Банк: подтверждённые параметры и границы

Сверено с публичной документацией 13.11.2026, без обращения в поддержку и без операций с боевым счётом.

- [Документация для r-логина](https://alfabank.ru/sme/payservice/internet-acquiring/docs/documentation-r/) указывает тестовый REST `https://alfa.rbsuat.com/payment/rest` и боевой `https://payment.alfabank.ru/payment/rest`. На [общей странице](https://alfabank.ru/sme/payservice/internet-acquiring/docs/documentation/) указан иной боевой адрес; тип логина определяет выбор, поэтому нельзя подставлять общий адрес для r-логина. Публичная документация не заменяет сверку выданных конкретному мерчанту координат.
- [REST банка](https://alfabank.ru/sme/payservice/internet-acquiring/docs/connection-options/api/rest/) описывает `register.do`, `getOrderStatusExtended.do` и `decline.do`; URL возврата должен быть абсолютным, а ответ регистрации не доказывает оплату. Набор и поведение параметров зависят от типа и версии мерчанта. Заказ, сумма, валюта и статус подлежат сверке.
- В проверке тестового мерчанта ранее зарегистрированный заказ вернул код валюты `810`, успешная регистрация могла не содержать `errorCode`; это не доказывает настройки боевого мерчанта. Фактические тестовые результаты и ограничения — в `docs/alfa-test-bank-check-2026-11-06.md` и `docs/deployment/2026-11-06-alfa-currency-fix.md`.
- Документация REST определяет `orderStatus=3` как отменённую авторизацию, `2` как полную авторизацию, `4` как возврат, `6` как отказ. Подтверждённую отмену можно архивировать после сверки номера, суммы и валюты; возврат требует отдельного сценария и не приравнивается к отмене.
- Для отмены незавершённого заказа документирован `decline.do`, но ранее выданному тестовому мерчанту в операции было отказано. Возможность конкретного мерчанта, обязательные параметры и подписанный callback для каждого контура не подтверждены; их отсутствие не маскировать под работающий сценарий.
- Точные допустимые домены платёжных форм конкретного мерчанта, боевой формат ответов, валюта, проверка доступа кандидата без создания заказа, фискализация и статус разрешений необходимо подтвердить до активации. Нельзя приравнивать опубликованный адрес API к подтверждённому списку хостов `formUrl`. Ограничивать подтверждённым allowlist без редиректов и произвольных запросов.
- [Фискализация для r-логина](https://alfabank.ru/sme/payservice/internet-acquiring/docs/fiscalization-r/) описывает настройки кассы; по доступным материалам не установлено, что для «Ласточки» касса и передача данных готовы. Способы и юридическая применимость не определяются автоматически по наличию API-реквизитов.
