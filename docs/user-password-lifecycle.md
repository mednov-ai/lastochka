# Пользователи и жизненный цикл пароля

Реализовано и проверено локально26.10.2026; затем по отдельному поручению поставлено backend/frontend0.11.0/V14. [Поставка и публичная приёмка](deployment/2026-10-26-user-passwords.md).

## Исходное состояние

Документированный сервер: backend0.10.0/frontend0.10.1/V13; живое окружение в локальном Apply не исследовалось; последующая поставка проверяла его заново. Следующая свободная миграция V14. Исходное дерево содержит прежние staged/unstaged/untracked изменения без исходного коммита; сброс/clean/stash не применялись. Снимок git status и SHA256 323 исходных файлов сохранён локально в artifacts/password-lifecycle-baseline перед правками. Новые правки вносятся адресно, прежняя функциональность сохраняется.

Пользователь уточнил: общий механизм для будущих ролей; сейчас создание только ADMIN. Прочитаны proposal/design/3 delta specs/tasks и применены Kotlin/React skills.

## Реализовано

- Раздел «Пользователи»: безопасный постраничный список, создание по имени/логину с назначенным временным паролем, адресный сброс другому ADMIN с подтверждением цели. Сейчас разрешена только ADMIN; жизненный цикл находится в общем сервисе аккаунта и не присваивает роль.
- V14 добавляет `must_change_password=false` и nullable срок; старые строки не переписываются. Для новых аккаунтов технический principal генерируется сервером, не показывается и не используется для почты.
- Временный пароль действует24 часа; PASSWORD_CHANGE_REQUIRED даёт только me/csrf/change/logout максимум15 минут, до истечения пароля. WebAuthn, административное чтение и команды закрыты сервером. Постоянный пароль даёт прежнюю FULL-сессию.
- Смена проверяет текущий пароль, политику, отличие и подтверждение. Сброс/смена атомарно увеличивают версию, отзывают старые сессии/challenge, сохраняют ключи и аудит. После собственной смены текущий браузер получает новую сессию/CSRF; сбой её сохранения не отменяет уже изменённый пароль.
- Конкурирующие команды повторно проверяют допуск под той же блокировкой studio_settings; ожидавшая блокировку команда не фиксируется после сброса. Конкурирующие изменения пароля проверяют ожидаемую ревизию; повтор создания не заменяет чужой хеш.
- OpenAPI экспортируется из backend, TypeScript генерируется штатно; секретные поля writeOnly. Новые ответы и страницы имеют no-store. Прежний frontend с временным входом остаётся без защищённого доступа.
- Образы и упаковка описывают PASSWORD_LIFECYCLE_V1/схему14. Старый backend без обязательной смены блокируется штатной проверкой, даже если способен читать таблицу.
