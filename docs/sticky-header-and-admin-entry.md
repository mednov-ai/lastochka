# Закреплённая мобильная шапка и служебный вход

24 октября 2026 года реализовано и по прямому поручению пользователя поставлено
`pin-mobile-header-and-relocate-admin-entry`: frontend **0.9.2**, backend **0.9.0**,
PostgreSQL **V12**. [Поставка, сохранность и откат](deployment/2026-10-24-sticky-header.md).
Изменение остаётся активным; архивирование в это поручение не входило.

## Поведение

До1000 px включительно общая шапка закреплена CSS sticky у верхнего края и
остаётся видимой при прокрутке до подвала и обратно. На320/375 px её высота80 px,
на768/1000 —88,375 px без верхней safe area. Целый SVG и основное действие
расположены одной строкой; при увеличении текста разрешён перенос и рост высоты.
Desktop сохраняет большой логотип и просторную композицию.

Гостевой кнопки входа в шапке нет. Выбранный пользователем вариант: небольшая
ссылка «Для администратора» в подвале и прежний /lastochka/auth/login для закладки.
Хоткей не добавлен. Вошедший ADMIN имеет прежний переход в кабинет, с короткой
мобильной подписью. Административные права и серверные правила входа не менялись.

Навигация18 px, телефон и основные действия16 px (размеры заданы через rem).
Ссылки получают плавный цветовой акцент и линию, кнопка — фон/тень с небольшим
движением; вход/выход200 ms. Focus-visible сохраняет контур и равнозначный акцент.
При reduced-motion переходы и движение отключены, на touch первое касание действует.

Измерение Header через один ResizeObserver уточняет общий отступ якорей и
фокуса, без scroll-listener и React-state на прокрутке. Без JS работает CSS-отступ,
масштабирующийся с текстом; в WebKit проверен200% режим. Модальные слои остаются
выше шапки; skip-link и возврат фокуса сохраняются.

## Проверка

- **32/32** целевых сценария Chromium/WebKit ×en-US/ru-RU ×375/1440:
  гость/ADMIN, геометрия320–1920 и обе стороны порогов, прямые страницы,
  вход из подвала и закладки, русские ошибки, keyboard-focus, hover со
  снимком промежуточного состояния, reduced-motion/touch/no-JS, DPR2,
  sticky до подвала, якоря,200% текста и изменение высоты/ориентации viewport.
- **11/11** прежних сценариев landing/landing-visual/format-composition
  на окончательной production-сборке. Видео/trace CPU×4: P95 **16,8/16,7 ms**
  на375/1440, кадров >50 ms и длинных задач0.
- **2/2** дополнительные проверки административной панели на375 px в
  Chromium/WebKit: открытие клавиатурой, поле/кнопка закрытия при уменьшении
  высоты окна до390 px, закрытие и возврат фокуса к инициатору без сохранения данных.
- Typecheck, build, форматирование, check:ui-language и строгая проверка change
  прошли. Языковая проверка:1024 фрагмента, нарушений0. Новые подписи берутся
  из ui-texts.ts. Прежнее предупреждение сборщика о смешанном импорте AuthForm остаётся.
- **20/20 публичных HTTPS-контекстов** после rollout; детали — в отчёте поставки.

В ходе реализации исправлены приоритет CSS-правила скрытия телефона на мобильных
экранах и WebKit-отступ якоря при no-JS/200%: резервная величина на em корректно
учитывает размер текста. После исправления выполнен полный повтор32+11.

Экранная клавиатура моделировалась уменьшением viewport; физическое устройство
этим браузерным прогоном не подменяется. Возврат фокуса административной панели
проверяется после клавиатурного открытия; WebKit по умолчанию не фокусирует кнопку
при мышином клике, поэтому такой клик не использовался как замена клавиатурному сценарию.

Доказательства исключены из Git: `artifacts/sticky-header/` содержит исходные
и итоговые снимки, hover-focus.webm, hover-samples.json, header-checks.log,
regression.log, panels.json, motion/ с видео/trace и измерениями.

Повторяемый запуск из frontend:

```sh
TEST_DATABASE_CONTAINER=lastochka-concept-postgres npx playwright test --config playwright.header.config.ts
```

Требуется изолированный local acceptance на localhost:5179; тест адресно очищает
два limiter bucket только в отдельной lastochka-concept-postgres, как прежняя
проверка SVG. Сценарии не предназначены для запуска против серверной БД.
