# Совместимость заявок и уведомлений — анализ перед изменением

Проверено по исходникам текущего рабочего дерева; сочетания ниже пока не являются результатами runtime-приёмки.

- V15 наследует из V10 `enrollment_requests`: `child_name` и `child_age` NOT NULL, возраст ограничен 0–17. Исторические значения, UUID, номер и ссылки необходимо сохранить. Очередь `telegram_outbox` имеет по одному событию на заявку; `enquiry_replays` хранит hash нормализованного запроса и 24-часовой ключ.
- Текущий backend требует оба детских поля, нормализует их до hash, сохраняет заявку, событие Telegram и replay в одной транзакции. Старые replay hashes нельзя инвалидировать при расширении DTO; это надо проверить с исходными и новым сериализаторами.
- Текущий SSR отправляет детские поля всегда, а при пустом возрасте передаёт -1. Поэтому новый frontend не может успешно отправить минимальную заявку старому backend. Старая форма при новом backend должна по-прежнему сохранять оба поля и проходить прежние replay.
- Текущая админка выводит оба детских значения без проверки null; старый backend читает `child_age` через `getInt`, что превращает SQL NULL в 0. Ни старый UI, ни backend не являются безопасным откатом после новых минимальных заявок без доказанной корректности и совместимых образов.
- Текущий endpoint состояния Telegram предполагает, что строка в очереди есть всегда. Если канал выключен, старой админке необходим совместимый ответ о невключённой доставке; нельзя оставлять бесконечное «Проверяем…» или ошибку 404. Существующие очереди и повторы сохраняются.
- Предполагаемый порядок: сначала протестированная аддитивная миграция и новый совместимый backend, затем новый frontend; до создания минимальных заявок проверить старую вкладку и обе пары. Нужны новый schema/concept gate и проверенные совместимые rollback-образы. Без фактических проверок и backup с restore порядок не разрешает поставку; откат БД поверх актуальных данных запрещён.
- Telegram в текущем backend уже реализован через серверный Bot API, outbox, ограниченные повторы и стабильный номер. Play&Say simple site выполняет синхронный `sendMessage`, поэтому переносить его зависимость успеха формы от доступности Telegram нельзя.
