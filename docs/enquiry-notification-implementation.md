# Заявки и уведомления — локальная проверка

## Завершение общей проверки — 29.10.2026

Задача 5.2 выполнена: полный запуск backend-тестов — 79/79, архитектурный анализатор — 8/8, Kotlin/Prettier и frontend typecheck/build прошли. Прежние замечания к форматированию `SafePushEndpoint.kt` и `admin-gesture.spec.ts` исправлены без изменения поведения. В изолированном стенде дополнительно прошли 60 из 64 браузерных сценариев заявок и настроек; четыре проверки отказа Push API для WebKit пропущены из-за отсутствия API в этом окружении. Регрессию календаря и быстрого первого ввода повторно проверили отдельно: 28 целевых и 24 регрессионных сценария, затем ещё 8 и 16 после последних правок. Результаты относятся к локальным Chromium/WebKit, а не физическим устройствам или реальной доставке на площадке.

## Миграция на восстановленной копии

28.10.2026 выполнен read-only `pg_dump` действующей тестовой базы V15. Копия восстановлена в отдельный локальный временный PostgreSQL; новый backend локально применил V16–V18 с выключенными workers и новой внешней generation. Readiness прошла, все 18 прежних таблиц совпали по отпечаткам, сохранены три ADMIN. Проверены настройки по умолчанию: Telegram выбран, browser push выключен. Временный dump, контейнер и локальные данные удалены. Действующая тестовая база не менялась.

Это проверка локальной JVM на восстановленной копии, а не поставка или проверка Linux/amd64 образа. Перед возможной поставкой требуется новая актуальная резервная копия с проверкой восстановления и проверка финального образа.

## Браузерные уведомления

На отдельном локальном стенде с одноразовым ADMIN и собственными ключами VAPID Chrome подписался на реальный push-сервис; новая тестовая заявка сохранилась и сообщение принято сервисом. После закрытия вкладки ADMIN браузер показал уведомление. Временные разрешения и профиль принадлежали автоматизированной проверке и удалялись после неё. Telegram при этом не настраивался.

## Восстановление новой схемы

На отдельной синтетической базе V18 создана подписка прежней generation и недоставленное событие, затем выполнен dump и restore в другую временную БД. Backend запущен с новой generation и без ключей push: старая подписка стала неактивной, ожидающее событие отменено, исходящие push не выполнялись. 18 бизнес-таблиц совпали по отпечаткам. Обе временные БД и копии удалены.

Публичные сценарии дополнительно проверены в Chromium/WebKit × en-US/ru-RU × 375/1440 px, включая выбор и замену занятия, конфликт закрытого занятия, no-JS и уменьшенную ширину формы. Для тестов отказа разрешения четыре контекста WebKit пропущены: Push API в этом окружении недоступен. Настоящий Web Push проверен на отдельном профиле Chrome для macOS; физические телефоны, Safari и push при закрытом браузере отдельно не принимались.

## Дополнительная приёмка кандидата

Финальный образ backend 0.15.0 для Linux/amd64 применил V16–V18 на свежей изолированной копии действующей тестовой базы V15. Все 18 исходных таблиц и три ADMIN совпали с исходным состоянием; workers отключены, использована новая generation. Исходные данные и временный контейнер удалялись после проверки. Старая заполненная гостевая форма, открытая до переключения frontend, успешно отправлена после переключения в Chromium и WebKit.

Backend `check`, архитектурный контроль и сборка JAR, frontend typecheck и проверка языка прошли. Фокус и телефонная маска проверены отдельными регрессиями. Из 56 сценариев формы и уведомлений прошли 52; четыре случая WebKit Push API пропущены, поскольку API отсутствует в тестовом окружении. Ещё 16 сценариев административного интерфейса прошли. В регрессии календаря 28 из 32 сценариев прошли; три повторных случая выявили нестабильное прежнее очищение названия во время открытия редактора, один повтор прошёл. Устаревшие тесты старого редактора также расходятся с уже поставленным компактным интерфейсом. Общий prettier check указывает на прежний посторонний файл `frontend/tests/admin-gesture.spec.ts`; проверка изменённых файлов прошла. Эти ограничения не следует считать успешной полной регрессией.

Для схемы V18 подготовлен и локально проверен совместимый запасной frontend `0.14.1-enquiry18-fallback`: он сохраняет прежнюю форму с детскими полями, но понимает новые заявки и состояние каналов. Он работает только с новым backend и не представляет полного отката функции. Прежние backend 0.13.0 и frontend 0.14.1 для V18 не подходят; возврат dump поверх новых данных недопустим, восстановление backend выполняется исправлением новой совместимой версии.
