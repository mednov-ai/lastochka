# Однострочная мобильная шапка

Изменение `compact-mobile-header-single-row`, 24.10.2026. Локальная реализация
и приёмка завершены. Поставка описывается отдельно в
[отчёте деплоя](deployment/2026-10-24-compact-mobile-header.md).

## Результат

На ширинах 375–1000 CSS px при обычном тексте логотип, «Записаться»/«Кабинет»
и кнопка с иконкой ☰ расположены в одной строке. Видимое слово «Меню» убрано,
русское доступное имя сохранено. При раскрытии ☰ заменяется крестиком.
Закрытая шапка закреплена, не перекрывает якорь, а список раскрывается ниже
строки управления и прокручивается при нехватке высоты.

Области нажатия не меньше 44×44 px, подпись основного действия не меньше 16 px.
Логотип остаётся полным SVG, без изменения файла. На 320–374 px и при 200% текста
допускается перенос. Отдельная строка до 430 px больше не задаётся принудительно;
декоративная стрелка CTA на этой ширине скрывается, полные подписи сохраняются.
Порядок управления и Tab: логотип → основное действие → меню.

No-JS вариант использует нативный `details/summary` в той же строке. Контейнер
details и его служебный блок используют `display: contents`, summary сохраняет
клавиатурное управление. Подтверждены его доступное имя и Enter/Space в Chromium
и WebKit; настоящая Chromium AX-модель показывает DisclosureTriangle и смену
expanded=false/true. Playwright не сопоставляет нативный summary с ARIA button,
поэтому такой поиск не используется как доказательство отказа доступности.

Существующий AuthProvider определяет вход клиентским запросом. SSR/no-JS даже
с ADMIN-cookie сохраняет прежнее публичное «Записаться»; после определения
входа с JS отображается «Кабинет». Серверная авторизация не менялась.

## Изменённые участки

- `frontend/app/ui/mobile-navigation.tsx`: доступное имя и SVG-иконки в обоих вариантах.
- `frontend/app/root.tsx`: согласованный DOM-порядок и отдельный класс декоративной стрелки.
- `frontend/app/styles.css`: компактный переключатель, no-JS раскладка и запасной отступ якоря.
- Проверки `mobile-menu.spec.ts` и `logo-header.spec.ts` уточняют границы и геометрию.

С принятой сборкой 0.9.8 сопоставлены 35 продуктовых исходников: изменились только
три указанных frontend-файла. Все 123 проверенных backend/API-файла сохранили SHA256.
Route discovery, совместимость старых клиентов и защита SSR-кнопки до гидратации
остались прежними. Новые зависимости, API и миграции отсутствуют.

## Локальная проверка

На Node 24.22.0 прошли typecheck, production build, проверка русского языка,
Prettier затронутых файлов и строгая проверка изменения OpenSpec.
После сборки собственный SSR перезапущен до browser-проверок.

- 32/32 сценария меню Chromium/WebKit × en-US/ru-RU × 375/1440, гость/ADMIN.
- 48/48 сценариев шапки, SVG и темы.
- 32/32 сценария форм, входа и административных панелей; записи проверки создавались
  только в изолированной локальной БД и удалялись штатной процедурой теста.
- 4/4 дополнительные проверки отключённой до гидратации кнопки, первого разрешённого
  нажатия, нативного no-JS переключателя и доступности.
- 448 измерений геометрии: по 224 с JS и без него. Ширины
  320/374/375/390/393/402/414/430/431/440/768/1000/1001/1440 px.
  Из них 320 замеров однострочной мобильной шапки: высота ≤88,375 px,
  расхождение центров ≤0,0078125 px, ширина SVG ≥151 px, без пересечений
  и горизонтального переполнения. На 375 px высота 80 px; на 320–374 ≤125,75 px.
- 96 проверок контраста меню, текст ≥6,62:1. Проверены пять пунктов из главной,
  заявки, расписания и кабинета, повторный якорь, resize, фокус/Escape/внешнее
  нажатие, touch/reduced-motion, no-JS, 200% текста и короткий экран.

Скриншоты 375/414/430 px для гостя/ADMIN и no-JS просмотрены. Доказательства —
`artifacts/compact-header/`: логи, `menu-local/`, `forms-local/`, `summary.json`,
`readiness.json`. Отдельный физический iPhone и VoiceOver не проверялись;
эмуляция WebKit не заменяет физическую приёмку. Удалённый CI не запускался.
