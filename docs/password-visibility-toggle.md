## Поведение

Общий `PasswordField` показывает глаз справа в поле. Он используется в прямом и модальном входе, повторном подтверждении входа, обязательной и добровольной смене, создании пользователя и назначении временного пароля. Показ независим для каждого поля; первое нажатие раскрывает, следующее скрывает введённое. Подпись кнопки для вспомогательных технологий сообщает русское действие и соответствующее поле.

Значение остаётся в одном input: сохраняются пробелы, регистр, выделение, каретка, имена и ограничения, current-password/new-password, ошибки и обычная отправка. Клавиатурная активация оставляет фокус на кнопке; мышь и касание из активного поля позволяют продолжить ввод на прежнем месте. Область нажатия44×44 CSS px, место для глаза и штатного автозаполнения зарезервировано внутри поля. При200% текста и на320 px глаз не перекрывает текст или подпись.

При сбросе формы видимость возвращается к скрытой. Успех, отмена, закрытие, выход и уход используют прежнюю очистку секретов; исправимая ошибка сохраняет ввод и выбранный режим. На SSR и до подключения обработчиков input скрыт, глаз отключён. Ранний ввод при подключении клиента не теряется. Новые сетевые запросы, browser storage, серверные поля и изменения политики паролей не добавлены.

## Локальная проверка

Пройдены64 уникальных браузерных сценария:40 целевых,16 жизненного цикла пароля и8 регрессионных подписи/фокуса входа. Матрица — Chromium/WebKit ×ru-RU/en-US ×375/1440, с дополнительными320 px,200% текста и контекстами с касаниями. Проверены независимость полей, пустой ввод, существующие ошибки, буквальное значение отправки, Enter/Space/Tab/Shift+Tab, Escape/возврат фокуса, отмена/очистка, SSR/ранний ввод/no-JS. Настоящая гостевая заявка без JavaScript прошла на отдельной локальной БД; собственные заявки и их очереди удалены адресно.

На отдельных локальных ADMIN проверены создание → временный вход → обязательная смена → добровольная смена → адресный сброс → повторная смена; серверные FULL/PASSWORD_CHANGE_REQUIRED и прежние ключи сохранены. Проверочные аккаунты удалены. Рабочий `info/password.txt` для этой реализации не читался; исходные аккаунты сайта не использовались для смены/сброса.

Дополнительное касание выявило, что отмена pointerdown в WebKit подавляет click. Отмена оставлена только для мыши; снимок выделения перед касанием и его восстановление сохраняют редактирование. Итоговые сценарии касания прошли в обоих браузерах. Один проект повторён7/7 после коллизии каталогов trace параллельных проверок; каталоги разделены. Это был отказ инфраструктуры проверки, последующий прогон успешен без дополнительной правки приложения. Снимки узких, широких, скрытых и раскрытых полей просмотрены.

Проверка1623 пользовательских фрагментов без нарушений, typecheck, production-сборка, форматирование затронутых файлов и strict OpenSpec validation прошли. Прежнее предупреждение общего статического/динамического импорта AuthForm остаётся предупреждением сборки.

## Границы приёмки

Касания проверены в браузерных контекстах с сенсорным вводом. Физические iPhone/Safari/VoiceOver и конкретные внешние менеджеры паролей отдельно не принимались. Проверка заполненного поля и атрибутов autocomplete не является полной проверкой всех менеджеров паролей. Публичная отправка гостевой заявки для этой поставки не выполнялась; реальная отправка принята локально.

Безопасные результаты — `artifacts/password-visibility/`, журналы — `runtime-data/password-visibility/`. Исходные материалы, результаты проверок и приватные рабочие файлы не добавляются в Git.
