# Композиция публичного расписания

Изменение `refine-public-schedule-layout`, 27.10.2026. Реализация и результаты проверок ниже дополняются по факту; это не свидетельство серверной поставки.

## Исходное состояние и границы

Изучены AGENTS.md, текущий статус, дельты расписания, зазора подписи/фокуса и мобильной шапки. Применяются vercel-react-best-practices: простое вычисляемое состояние, без новых зависимостей и эффектов для оформления. SchedulePeriod используется публичным маршрутом; общие toolbar/notice/page и оформление SessionDetails затрагивают другие страницы, поэтому новые правила ограничены корнем `.public-schedule`.

Исходные снимки: `artifacts/schedule-layout/before/{375,1440}-{empty,filled}.png`. Данные занятий синтетические, перехвачены только в браузере; БД и публичные данные не менялись. Видны разная высота поля/кнопок, подпись в строке вплотную к дате и две отдельные бирюзовые плашки при пустой неделе. Обрезание даты на исходном пользовательском снимке не установлено.

## Реализация

Панель недели получила две смысловые группы, нативную дату с подписью сверху, зазором12px и собственным фокусом. На телефоне быстрые команды растягиваются до одинаковой высоты, последовательность перехода/даты перестраивается при320px. CSS ограничен `.public-schedule`; карточки переносят содержимое, заголовки имеют локальные интервалы. Поле даты учитывает дополнительный отступ прокрутки при фокусе под закреплённой шапкой.

Пустая неделя показывает один блок с предложением выбрать другой период, пояснением об отсутствии брони и основной кнопкой. При наличии занятий ниже карточек остаётся спокойный блок помощи. Запросы/часовой пояс/пагинация и предвыбор занятия сохранены, новых зависимостей нет.

Снимки до/после находятся в `artifacts/schedule-layout/`; визуально просмотрены широкая пустая неделя, WebKit375, WebKit320 с карточками и375/200%. Первый целевой прогон выявил особенность клавиатурного управления WebKit (полный проход через Alt+Tab); тест приведён к уже используемому проектом режиму, приложение для этого не менялось. Первый полный прогон редактора потерял один файл трассировки из-за общего выходного каталога двух прогонов; повтор с отдельным каталогом завершился успешно:32/32. Это не свидетельство ошибки интерфейса.

Для сквозной регрессии создана отдельная локальная БД/контейнер `lastochka-editor-postgres`, backend из ранее принятого артефакта0.11.0/V14, отключены workers. Отдельные SSR и proxy направлены только на эту БД. Публичные занятия для визуальной матрицы не создавались; данные в целевых сценариях перехватываются браузером. Физические Safari/iPhone/VoiceOver отдельно не проверялись.


Публичная проверка0.11.1 выявила расхождение регистра дня недели между Node/Chromium и WebKit (пн/Пн), приводившее к React418. В0.11.2 обе границы диапазона приводятся к нижнему регистру. Исправление подтверждено32 локальными сценариями, включая слушатель pageerror до первого открытия; ошибка не подавляется. Дополнительные геометрические замеры — `artifacts/schedule-layout/geometry.json`:12px от подписи до поля, ширина поля181–200px, горизонтальное переполнение отсутствует.
