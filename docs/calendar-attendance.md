# Календарь, переносы и «Приду»: локальная приёмка 23.10.2026

Реализовано изменение `improve-calendar-and-client-confirmation`. Серверная
поставка не выполнялась; опубликованные frontend 0.4.1 и backend 0.3.0 не менялись.
Эксплуатация, ключи, очистка и будущая поставка описаны в
[calendar-attendance-operations.md](calendar-attendance-operations.md).
Этот отчёт фиксирует состояние до поставки. По последующему поручению пользователя
в тот же день выполнена [серверная поставка 0.5.0](deployment/2026-10-23-calendar-confirmation.md).

## Результат

- Администратор видит весь выбранный период: День / Неделя / Список, понедельник,
  московское время, выходные, «Сегодня», навигацию и выбор дня на телефоне.
  Выборка не зависит от первой страницы общего списка. При техническом пределе
  1000 занятий возвращается явная ошибка с предложением сузить период.
- Панели занятия и записи открываются сразу в видимой области, удерживают фокус,
  закрываются Escape и возвращают фокус кнопке. Состав имеет собственную пагинацию.
- Перенос занятия и перенос ребёнка имеют отдельные формы, серверный preview
  на пять минут и явное подтверждение. Состав/версии/места перепроверяются
  в транзакции. Drag на компьютере сохраняет длительность и открывает тот же preview.
  На touch остаются прокрутка и кнопочные формы; пересекающиеся черновики доступны.
- Клиент открывает одну одобренную запись по письму без входа и нажимает
  «Подтверждаю, приду». Ответ показан отдельно от одобрения ADMIN. Неответ не
  освобождает место. Перенос и изменение согласуемых условий отзывают ссылки,
  сбрасывают прежний ответ и создают актуальное письмо для CONFIRMED.
- Закрытие приёма или изменение одной вместимости сохраняет ответ. ADMIN может
  перевыпустить приглашение с лимитами. Уже полученный ответ на те же условия
  сохраняется. Существующие записи мигрируют без автоматической рассылки.

Итоговые 34 сценария запускались с `TEST_PRODUCTION=1` через
`scripts/calendar-browser-checks.py` для `auth-modal`, `booking`,
`calendar-attendance`, `format-composition`, `landing-journey`, `landing-visual`,
`landing` и `routing`. Два compatibility и один HTTPS-сценарий используют
отдельные локальные helpers. После расширения проверки потери ответа повторно
пройден весь набор из десяти `calendar-attendance` сценариев.

Backend-проверки включают полную неделю из 35 занятий, границы полуночи и
плотность 1001; независимые цели переноса за первой страницей; TTL, повтор,
подмену контекста/назначения, CSRF/Origin, роли, лимиты, отзыв после восстановления
аккаунта, ciphertext/AAD/keyring, retry/SKIPPED и очистку payload/писем MailHog.

Параллельные команды проверены на PostgreSQL: ответ против переноса, ответ против
отмены, ответ против восстановления пароля и два ADMIN с действующими previews
за последнее место. Отменённая/перенесённая запись не сохраняет старый «Приду»;
восстановление аккаунта запрещает дальнейшее использование разрешения. Ответ,
успевший завершиться до восстановления аккаунта, остаётся историей. Дублей аудита
и лишних писем не возникает; при конкуренции за цель проходит только один перенос.

В браузере проверены 35 карточек, участники 20+5, цели 20+14, панели 375/768/1440,
Tab/Escape/возврат фокуса, поздний ответ прежнего периода, две ссылки в двух вкладках,
no-JS fallback, touch и часовой пояс America/Los_Angeles с отображением МСК.
При потере HTTP-ответа после успешного confirm кнопка доступна для повтора,
сервер возвращает уже сохранённый результат. Новый браузер с consumed ссылкой
не получает сведения повторно. Существующий вход ADMIN не подменяется.

## Граница безопасности

Случайный секрет 32 байта передаётся во fragment письма и рано удаляется из URL;
его нет в SSR, storage, запросах URL или referrer. В grants хранится hash,
в outbox — AES-256-GCM ciphertext с ключом вне БД. Ссылка ограничена одной записью,
получателем/authVersion, revision и внешней generation; TTL — min(72 часа, начало).
Отдельный browser-контекст действует до 15 минут, не создаёт FULL/SecurityContext.
POST требует Origin, отдельный CSRF и nonce показанной записи. API не открывает
кабинет, список семьи, изменение или отмену записи. Публичная подпись ребёнка —
«Ваш ребёнок»: текущая модель не имеет отдельного безопасного поля имени.

Модель остаётся bearer-доступом: переславший письмо передаёт право ответа.
Аудит не утверждает проверенную личность. Активный почтовый сканер, способный
исполнить JS и имитировать нажатие, неотличим от обладателя ссылки; обычный
просмотр не подтверждает запись и не потребляет разрешение.

закрытый MailHog и loopback-порты 55433/11027/18027/8181/5174. Существующие local,
