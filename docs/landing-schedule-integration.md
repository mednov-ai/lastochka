# Расписание как раздел главной

Изменение `integrate-schedule-into-landing`,27.10.2026. До окончания приёмки этот документ фиксирует ход локальной реализации, а не серверную поставку.

## Основа и границы

Сайт находится на тестовой площадке; production-поставки не было. Пользователь выбрал полноценное расписание на главной и удаление отдельного публичного `/schedule` без совместимости/редиректа. API занятий и административный `/admin/schedule` сохраняются.

Изучены AGENTS/статус, основная и активные спецификации расписания/темы/шапки/фокуса. Применяется vercel-react-best-practices: локальное состояние раздела, отсутствие новых зависимостей и обязательного запроса расписания в корневом loader, обработка событий для повторного якоря, стабильный ключ раздела. Рабочая копия до правок сохранена по контрольным суммам в `runtime-data/landing-schedule/baseline.json`. Исходные снимки375/1440 главной и отдельной страницы — `artifacts/landing-schedule/before/`; публичные данные для них не менялись.

## Реализация

Логика прежнего маршрута перенесена в ScheduleSection, публичный route и его файл удалены. Главная вставляет секцию после последнего видимого formats, иначе перед steps/contacts, иначе в конце, не изменяя published JSON. Единственная основная область страницы, заголовок раздела h2, дни h3 и карточки h4. Заявка/предпросмотры сохраняют исходный уровень заголовка по умолчанию.

Все ссылки просмотра, включая ссылку после отправки заявки, ведут на `/#schedule`. Общий SectionLink повторно показывает текущий якорь после закрытия меню; модифицированные клики сохраняют обычное открытие ссылки. Компьютерная шапка показывает все пять пунктов. Без JS заголовок и ссылка на серверную заявку остаются доступны; неработающее недельное управление скрыто и показано русское объяснение.

Миграции/API/backend не меняются. Для сквозных проверок используется отдельная локальная БД `lastochka_editor` в собственном контейнере `lastochka-editor-postgres`, принятый артефакт backend0.11.0/V14, workers выключены. Тестовые данные не создаются в существующих пользовательских БД.


## Первые уточнения проверки

Встроенная секция не наследует вычисляемые для полноэкранных блоков горизонтальные поля: иначе ограниченная ширина секции на1920px давала чрезмерные отступы и перенос управления. Поставлены локальные поля20–48px. Старые проверки четырёх пунктов заменены пятью; в матрице расписания принудительный reload отделяет синтетические варианты, так как повтор того же hash теперь корректно сохраняет компонент/выбранную неделю.

Регрессия обнаружила потерю фокуса скрываемого пункта при пересечении1000/1001px. Мобильная навигация запоминает нахождение фокуса внутри управления и при скрытии переводит его на логотип, даже если браузер уже сбросил activeElement в body. В тестах реальных OPEN/CLOSED/DRAFT/CANCELLED каждому контексту выделена отдельная будущая неделя, чтобы соседние fixtures не смешивались в одном периоде.


## Проверки локально

-40 новых сценариев интеграции:32 навигации/геометрии/no-JS/ревизий контента и8 реальных статусов занятий/предвыбора, Chromium/WebKit ×ru-RU/en-US ×375/1440, прошли.
-32 сценария композиции/календарных правил/пагинации/ошибок/запоздавшего ответа/первоначального подключения,32 меню и шапки,32 редактора/подбора/серверной отправки заявки без JS и24 телефонной формы прошли.
-В матрицах ширины320/375/768/1000/1001/1100/1280/1440/1920,200% текста, целые поля/фокус, клавиатура, touch и reduced-motion. После исправления памяти фокуса32 сценария меню прошли целиком.
-Готовая сборка: typecheck, проверка1619 пользовательских фрагментов без нарушений и форматирование изменённых файлов прошли; сохраняется прежнее предупреждение сборщика об одновременном статическом/динамическом импорте auth-form.
-Прокрутка с CPU×4: P95=16,8ms на375 и1440px, доля кадров>50ms=0, long tasks отсутствуют. Видео и trace — `artifacts/landing-schedule/motion/`.

Проверка первоначального подключения не использует немедленный двойной reload: WebKit сообщает ошибки доступа для штатно прерванных запросов предыдущего документа. Синтетические варианты теперь разделяются переходом через пустой документ, первый вход проверяется без отмены начального запроса. Сценарий очистки scroll-listeners обновлён: переход к якорю не размонтирует главную, слушатели сохраняются без роста, затем уход в заявку проверяет очистку. Физические Safari/iPhone/VoiceOver отдельно не принимались.


Локальная приёмка завершена:168 различных браузерных сценариев прошли (40 интеграции,32 композиции/правил расписания,32 меню,32 редактора/заявки,24 телефонной формы и8 лендинга/прокрутки). Финальная проверка слушателей при переходе к якорю и затем в заявку прошла после обновления ожидаемого назначения ссылки. Снимки375/1440, заполненная/пустая недели и контрольные ширины просмотрены. Код backend, миграции и API совпали с исходными контрольными суммами; сохраняются только согласованные frontend-правки, проверки и документация. Изменение13/13, готово к обновлению тестового сервера, не архивировано.
