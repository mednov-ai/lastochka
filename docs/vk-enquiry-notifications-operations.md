# Уведомления о заявках во ВКонтакте

## Подключение для владельца сообщества

1. В управлении сообществом во ВКонтакте включите «Сообщения сообщества». В разделе «Настройки для бота» включите возможности ботов и разрешите добавлять сообщество в беседы.
2. Создайте закрытую беседу сотрудников. На странице сообщества нажмите «Пригласить в беседу» и выберите её.
3. Откройте «Управление → Работа с API → Ключи доступа». Создайте отдельный ключ с доступом к сообщениям сообщества. Вводите ключ только в кабинете «Ласточки».
4. В кабинете откройте «Заявки → Уведомления о заявках → ВКонтакте». Сохраните ключ, выберите беседу и нажмите «Отправить тестовое сообщение». Проверьте, что оно пришло в нужную беседу, затем включите уведомления.
5. Для замены выберите «Заменить ключ» и повторите проверку. Рабочая беседа показана до подтверждения новой настройки. Если выбрана другая беседа, ожидающие сообщения прежней беседы останавливаются. При отсутствии беседы в списке проверьте приглашение сообщества и загрузите список заново.

В блоке «Уведомления браузера» переключатель «Для студии» управляет уведомлениями о новых заявках. «Подключить это устройство» отдельно подключает текущий браузер. Если загрузка одного из блоков не удалась, используйте «Повторить загрузку» в этом блоке.

## Подготовка среды и восстановление

- Примените V34 к отдельно проверенной базе. Миграция добавляет таблицы `vk_enquiry_settings` и `vk_enquiry_outbox`, а также последовательность `vk_enquiry_random_id_seq`. Если роль миграции отличается от роли приложения, проверьте права чтения и изменения двух новых таблиц и право USAGE на последовательность по действующим правилам раздельных окружений.
- В каждом окружении создайте отдельный 32-байтовый ключ шифрования VK. Сохраните его в формате Base64 в защищённом файле `<key-id>.key`, читаемом только оператором и серверным процессом. Передайте backend каталог файла через `LASTOCHKA_VK_KEY_DIRECTORY`, ID через `LASTOCHKA_VK_KEY_ID` и окружение через `LASTOCHKA_VK_ENVIRONMENT` со значением `test` или `production`. В контейнере каталог подключается для чтения пользователя приложения UID 10001. Для тестовой и рабочей сред нужны разные материалы шифрования и разные адресаты.
- Для восстановления PostgreSQL и серверных ключей используйте раздельные резервные копии. При смене ID ключа оставляйте прежний файл доступным, пока записи с этим ID используются. Замена ключа сообщества из кабинета сохраняет новый шифротекст под текущим ID. Проверьте восстановленную копию отдельно от рабочего окружения.
- На изолированном VPS backend по умолчанию подключён только к внутренней сети Docker. Перед приёмкой оператор настраивает и проверяет исходящее HTTPS-соединение backend с `api.vk.com` и нужными сервисами браузерного push. Политика входящего TLS остаётся TLS 1.2.
- `LASTOCHKA_WORKERS_ENABLED` управляет фоновыми отправками. `LASTOCHKA_VK_WORKER_ENABLED=false` позволяет отдельно приостановить отправку ВКонтакте при оставленном браузерном push. Выключение канала в кабинете прекращает постановку **новых** заявок. Задания для того же адресата сохраняются и обрабатываются после возобновления обработчика.
- Перед переключением дождитесь завершения старого обработчика Telegram. Для отката используйте проверенную V34-совместимую сборку с отключённым Telegram. До приёмки можно оставить ВКонтакте выключенным для новых заявок. При проблеме с ключом или получателем проверьте состояние в кабинете и выполните повтор только для исходной беседы.
- При отдельно согласованной поставке сначала проведите приёмку на test с синтетической заявкой. Подтвердите получение в закрытой беседе и показ на подписанном браузере при закрытой вкладке. Эти проверки покрывают оставшиеся сценарии уведомлений из `simplify-enquiry-form-with-age-directions` после перехода на ВКонтакте.
