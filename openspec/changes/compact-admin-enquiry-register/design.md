## Context

На test измерена существующая страница в Chromium с подставным API. При 25 строках первая строка начинается на 435 px при размере 1440 × 900 и на 532 px при 375 × 812. Типовая строка занимает соответственно 102 и 159 px. До нижней навигации нужно прокрутить примерно до 2981 и 4507 px от начала документа. При четырёх записях переходы отсутствуют. При раскрытии настроек уведомлений первая строка уходит ниже начального экрана. На сервере уже есть выдача по 25 записей и общее количество.

## Goals / Non-Goals

**Goals**

- Увеличить число полностью видимых типовых строк с 4 до минимум 6 на десктопном размере и с 1 до минимум 2 на мобильном размере в той же проверке, при свёрнутых уведомлениях.
- Показать число записей над списком и разместить переходы между страницами после последней строки.

**Non-Goals**

- Фильтрация, поиск по произвольному тексту и выбор размера страницы остаются за пределами изменения.

## Decisions

- На широком экране расположить контакт, пожелание и время в трёх компактных визуальных группах. Номер объединить с датой или именем в одной строке, телефон оставить видимым. Для типовой записи ориентир 56–64 px. На телефоне использовать одну общую строку-запись с переносом внутри неё. Контакт поставить первым, затем пожелание и метаданные. Ориентир 88–104 px. Длинные данные и увеличение текста могут естественно увеличить высоту. Сохранить единое действие открытия на всю строку с видимым фокусом.
- Заменить отдельную фразу о связи с заявителем полезным обзором «1–25 из 56». Настройки уведомлений сгруппировать рядом в компактной верхней области. Они свёрнуты при входе и открываются по запросу пользователя.
- Переиспользовать существующие кнопки страниц и серверный размер 25. Над списком показывать диапазон. После списка разместить единственный блок переходов. На телефоне кнопки могут переноситься с сохранением области касания 44 × 44 CSS px. Добавить переход по номеру страницы в адресе с параметром `page`, начиная с 1. Первая страница обходится без параметра. Запрос к API преобразует значение в нулевой индекс, сохраняя остальные параметры, включая `enquiry`.
- После успешного перехода показать начало списка и объявить диапазон для вспомогательных технологий. Сохранять рабочие сценарии защищённой ссылки и возврата фокуса из карточки. При перевыборе страницы использовать существующую защиту от устаревших ответов. При ошибке дать повтор без показа чужого диапазона.
- Уменьшение размера серверной страницы рассмотрено. Существующие 25 записей достаточно для первого выпуска при компактных строках и доступной навигации. Такое решение сохраняет текущий API и все уже проверенные сценарии открытия карточки.

## Risks / Trade-offs

- Уплотнение способно ухудшить читаемость. Проверить длинные записи, увеличение текста до 200%, клавиатуру и переходы на ширинах 320, 375 и 1440 px.
- Обновление страницы во время поступления заявок может изменить границы существующей постраничной выборки. Сохранить серверную сортировку и проверять переходы на стабильном наборе данных.
