## MODIFIED Requirements

### Requirement: Устойчивая доставка и контролируемый повтор ВКонтакте

Задания ВКонтакте SHALL переживать перезапуск. Временные ошибки SHALL повторяться с ограниченными задержками и числом попыток. Ошибка всего запроса и ошибка отдельного получателя с одним кодом ВКонтакте SHALL классифицироваться одинаково. Недоступность беседы, непригодный ключ и прочий отказ ВКонтакте SHALL иметь разные безопасные причины. Все попытки одного логического задания SHALL использовать один идентификатор защиты от дублей у ВКонтакте. Успех SHALL фиксироваться только по положительному ответу API с идентификатором сообщения и обозначать принятие API. Кабинет SHALL показывать ожидание, отправку, принятие API либо безопасную причину окончательного отказа отдельно от push. Допущенный ADMIN и STAFF с доступом к заявкам SHALL иметь доступ к штатному повтору неудавшегося задания в исходную беседу при действующем подключении к ней. Повтор SHALL проверять CSRF, ограничение частоты, отсутствие параллельного повтора и записывать аудит. При уже принятой доставке повтор SHALL быть недоступен.

#### Scenario: Временная ошибка и перезапуск

- **WHEN** запрос завершился тайм-аутом, ВКонтакте ограничил частоту либо обработчик перезапустился
- **THEN** задание сохраняется, допустимый повтор использует тот же идентификатор отправки, а заявка и её номер остаются единственными.

#### Scenario: Повтор после замены ключа для той же беседы

- **WHEN** ADMIN успешно проверил новый ключ того же сообщества и беседы, затем пользователь с правом повтора запускает повтор неудавшегося задания
- **THEN** попытка относится к исходной заявке и беседе, аудит содержит автора и время, а состояние push не меняется.

#### Scenario: Отказ API в успешном HTTP-ответе

- **WHEN** ВКонтакте возвращает HTTP 200 с объектом ошибки или без подтверждённого идентификатора сообщения
- **THEN** карточка показывает ожидание повтора или отказ по классификации результата, а принятие сообщения не фиксируется.

#### Scenario: Временная ошибка получателя

- **WHEN** ВКонтакте возвращает HTTP 200, а для выбранной беседы сообщает о внутреннем сбое или ограничении частоты
- **THEN** карточка показывает ожидание повтора, следующая попытка выполняется автоматически с тем же идентификатором отправки.

#### Scenario: Отказ, не связанный с беседой

- **WHEN** ВКонтакте отклоняет отправку из-за отключённых возможностей бота, параметров запроса или требования дополнительной проверки
- **THEN** автоматические повторы прекращаются, кабинет предлагает проверить права ключа и возможности бота, а не наличие сообщества в беседе.

#### Scenario: Приёмка настроенного канала

- **WHEN** на test выполнена отдельно порученная проверка с настоящим сообществом и синтетической заявкой
- **THEN** фиксируются принятие API и подтверждённое получение сообщения в нужной беседе, без реальных контактов и без публикации ключа.
