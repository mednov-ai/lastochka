## Context

Причина изменения — в `proposal.md`. В исходниках заявки используется `type="tel"`, пример номера и лимит 30 символов; в `admin.tsx` есть второе телефонное поле черновика оплаты. Общий backend `ContactValidation.phone` уже проверяет одиннадцать цифр с начальной `7`/`8`, допускает `+()- ` и хранит `+7XXXXXXXXXX`. Новая транспортная модель и миграция не нужны.

`RussianForm` управляет `ValidityState`, `setCustomValidity`, связанными полевыми ошибками и их снятием на input/change. Заявка отправляется серверным action и работает без JavaScript. Требования фокуса действуют из активного `fix-form-focus-label-overlap`; прочие поставленные изменения сохраняются.

Дизайн необходим из-за взаимодействия защищённого префикса, каретки, мобильных событий ввода, нативной проверки и SSR.

## Goals / Non-Goals

**Goals:**

- Разделить неизменяемый код страны, национальные цифры и декоративный шаблон, исключив отправку подчёркиваний или вымышленных цифр.
- Дать обеим формам один компонент и одну политику разбора/форматирования, включая данные, возвращённые после отказа.
- Обеспечить работающую исходную форму и непрерывность ввода при гидратации.

**Non-Goals:**

- Международные номера, выбор страны, проверка существования номера, SMS и определение оператора.
- Изменения backend-политики телефона, API/генерируемых DTO, схемы, существующих контактов, Telegram или платёжного провайдера.
- Перестройка остальных форм и публикация в рамках propose.

## Decisions

### 1. Префикс вне редактируемого текста, цифры отдельно от оформления

В общей визуальной рамке разместить постоянный `+7` и один `type="tel"` input национальной части. Префикс не является редактируемым контролом и не получает Tab. Касание рамки/префикса переводит фокус в национальную часть. Контур `focus-within` охватывает всё поле, сохраняя существующий зазор подписи 12 px.

При работающем JavaScript состояние — строка из 0–10 ASCII-цифр. Отображаемая национальная часть форматируется как `900 123-45-67`. Декоративный слой показывает только оставшиеся позиции `___ ___-__-__`, совпадает по геометрии с вводимым текстом, не перехватывает касания и скрыт от accessibility tree. Постоянная русская инструкция объясняет код страны и десять цифр; placeholder не является единственным объяснением. Макет должен работать и при 200% текста без наложения введённых цифр и подсказки.

Альтернатива — один input с `+7` внутри и восстановлением стёртого префикса в обработчике — оставляет код страны редактируемым до JavaScript и усложняет выделение. Обычный placeholder исчезает при вводе. Эти варианты не обеспечивают требуемую защиту.

### 2. Один разбор для ввода, вставки и исходного номера

Общий модуль различает национальные цифры и целый номер. Ровно десять цифр — национальная часть, включая начальные `7`/`8`; ровно одиннадцать с начальной `7`/`8` — полный номер со снятием первой цифры. Для полного номера допускаются разделители backend `+()- ` и обычные неразрывные пробелы из буфера/автозаполнения, преобразуемые в обычные пробелы до проверки. Плюс допустим только как начальный знак полного `+7`. Буквы, другой код страны, добавочные номера и лишние цифры не удаляются молча: весь такой ввод отклоняется.

Обычный посимвольный ввод относится к национальной части: нельзя срезать первую `7`/`8` на основании частично введённой строки. Вставка полного номера или автозаполнение заменяют национальную часть целиком; частичная вставка цифр действует на текущее выделение. При превышении ёмкости вставка отменяется целиком с русским сообщением; один лишний набираемый символ просто не добавляется. Номер не усекается через `slice(0, 10)`.

Не полагаться только на `maxLength`: браузер может обрезать полную вставку до того, как код распознает её префикс. Перехват paste/beforeinput должен получить исходную вставку целиком. Резервный input/change обрабатывает мобильные изменения и автозаполнение, если beforeinput не предоставил данные. Альтернатива с одним replace/filter для всех событий теряет информацию о коде страны и скрывает ошибочные вставки.

### 3. Каретка и история относятся к позициям цифр

Преобразовывать выделение отображаемого текста в диапазон индексов цифр, применять вставку/удаление к этому диапазону и возвращать каретку к соответствующей позиции в новой форматированной строке. Backspace/Delete рядом с разделителем выбирают предыдущую/следующую цифру. Операция, которая не меняет цифры, не перемещает каретку. Сохранить действия клавиатуры, выделение и undo/redo; если управляемый input нарушит нативную историю, обеспечить историю состояний цифр и выделения для этого одного поля, без перехвата команд других полей.

Не использовать только keydown: он не покрывает касания, вставку, автозаполнение и экранную клавиатуру. Альтернатива с форматированием только на blur не выполняет требование автоматических разделителей во время ввода.

### 4. Внутренняя форма преобразуется в прежнее API-поле

Национальная часть получает внутреннее имя формы, например `phoneNational`; это состояние UI, не новый DTO. Общий помощник проверяет форму национальной части и собирает `phone: '+7' + nationalDigits`. Он используется серверным action заявки и сборкой payload черновика. Национальная часть должна содержать ровно десять цифр и только разрешённое оформление; подчёркивания, буквы и избыток не проходят через очистку до допустимого номера. Неверная национальная часть возвращает полевую ошибку `phone` до обращения к API.

Серверный action должен также принимать прежнее полное поле `phone`, если новое внутреннее поле отсутствует: это сохраняет отправку вкладок, открытых до обновления. Для старого поля использовать прежний путь серверной проверки; если оба поля присутствуют, не выбирать незаметно противоречивые значения. Ошибки, возвращаемые из API как `fieldErrors.phone`, по-прежнему связываются с видимым контролом. Значения ответа action восстанавливаются в национальную часть без удвоения `+7`; прочие поля и ключ повтора сохраняются.

Исходный HTML показывает фиксированный `+7`, пустой/предзаполненный input из национальных цифр с `required`, `inputMode="numeric"`, `maxLength=10`, pattern ровно десяти ASCII-цифр и инструкцией для no-JS: «Введите 10 цифр после +7». Декоративный шаблон доступен сразу. На серверной отправке эти цифры проверяются и соединяются с кодом страны. Без JavaScript не обещаются автоматическое форматирование и вставка полного номера: пользователь вводит национальные цифры. После подключения JavaScript форматирование включается, а обработка вставки учитывает её полную длину до нативного ограничения.

В режиме JavaScript заменить pattern национальных цифр на pattern полного оформленного суффикса и снять исходный `maxLength=10`: он считает разделители и способен обрезать автозаполнение. Лимит десяти цифр обеспечивает обработка исходных операций, а полноту — согласованная нативная/собственная проверка. После любого изменения сначала установить допустимое отображаемое значение, затем обновить проверку и выделение. Отдельно подтвердить, что полный суффикс из 13 символов проходит проверку, а автозаполнение с избытком цифр отклоняется до усечения.

Перед установкой управляемого значения при гидратации прочитать фактическое значение DOM и сохранить ранний ввод/автозаполнение. Поле не должно ждать JS в disabled-состоянии. API backend сохраняет прежнюю независимую проверку; никакие существующие номера в БД не переписываются.

### 5. Один владелец полевой ошибки

Добавить точную русскую причину телефона в общий каталог и узкую поддержку телефонного ограничения в `RussianForm` либо его согласованном расширении. На пустой/неполный номер возвращается «Введите 10 цифр телефона после +7». Отдельные причины неверной вставки не теряются при следующем invalid-событии. Согласовать порядок обработчиков: снятие прежней ошибки общим onInputCapture не должно стирать новую ошибку компонента, а одна ошибка не должна создавать две конкурирующие плашки/ссылки.

Использовать нативные ограничения и доступные постоянные сообщения, включая `aria-describedby`/`aria-invalid`, кнопку и Enter. Ошибка вставки снимается следующим допустимым изменением. При ошибке другого поля или отказе API номер остаётся введённым. Альтернатива с отдельным локальным alert и независимым `setCustomValidity` конфликтует с текущим сбросом ошибок `RussianForm`.

### 6. Проверки сосредоточены на пользовательском поведении

Основная матрица: Chromium/WebKit × en-US/ru-RU × 375/1440. Целевые проверки покрывают непрерывный ввод, границы разделителей, обе клавиши удаления, каретку/выделение/undo/redo, десять/одиннадцать цифр, полную и частичную вставку, отказ переполнения, автозаполнение, кнопку/Enter, исправление и восстановление после отказа. Проверить обе формы и предзаполнение ADMIN из заявки/черновика, используя собственные временные данные.

Отдельно проверить 320/390/430/768 px, 200% текста, no-JS, ранний ввод при задержке гидратации, reduced-motion и доступные имена/фокус. Не выдавать эмуляцию WebKit и программное событие автозаполнения за физическую приёмку Safari/iPhone/VoiceOver; при доступном устройстве проверить реальную клавиатуру и автозаполнение, иначе записать ограничение.

## Risks / Trade-offs

- Мобильное удаление и автозаполнение имеют разные последовательности событий → проверять результат и каретку в обоих движках, иметь резервный input/change, не ограничиваться keydown.
- `maxLength` может обрезать полную вставку ещё до нормализации → обрабатывать исходную вставку целиком; отдельно проверить «допустимый номер + лишняя цифра» и автозаполнение.
- Управляемое поле и форматирование могут ломать undo/redo → сохранять историю цифр и выделения при необходимости, проверить несколько последовательных правок и отмен.
- Маска может перекрыть цифры при увеличении шрифта → одинаковые метрики слоёв, проверка 200% и узких экранов, без фиксированной ширины, вызывающей переполнение.
- Телефон разбит на префикс и input → одно понятное доступное имя/пояснение о `+7`, один фокус; копирование выделенной национальной части само по себе не содержит код страны.
- Без JavaScript нет автоматических разделителей → постоянный шаблон и явная инструкция десяти цифр, нативные ограничения и полноценная серверная проверка/отправка.

## Migration Plan

1. В apply реализовать общий компонент и подключение обеих форм, сохранив старое поле `phone` для открытых вкладок и прежний API. Данные и миграции не менять.
2. Пройти целевые браузерные проверки, `check:ui-language`, typecheck, production build и форматирование затронутых файлов; записать результаты и пределы приёмки в отдельном отчёте. Обновить состояние проекта по факту реализации.
3. Поставку выполнять по отдельному поручению как frontend-only после актуального preflight, проверенного backup/restore и проверки совместимости со старой вкладкой. Не перезапускать backend/БД и не затрагивать общие Nginx/TLS/соседние сайты.
4. При разрешённой поставке подтвердить новую маску на публичном HTTPS, сохранность ADMIN/сессий/ключей/данных и старых assets, удалить только собственные fixtures. Версию и допустимый образ отката определить по фактическому состоянию перед поставкой.
5. Откат — на предыдущее принятое совместимое frontend image без восстановления старого dump поверх текущих данных; сохранённые заявки/черновики остаются в прежнем формате. Архивирование отдельное, после фактического выполнения и синхронизации спецификаций.
