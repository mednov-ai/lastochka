## Why

Сейчас добавить администратора или восстановить его пароль можно только закрытой процедурой оператора, а пользователь не может сменить свой пароль. Нужны создание аккаунта с временным паролем, обязательная замена при входе и самостоятельная смена пароля; механизм должен подходить будущим ролям.

## What Changes

- В административном разделе появляется список пользователей, создание по имени и уникальному логину с назначенным администратором временным паролем, повторное назначение временного пароля существующему пользователю.
- По уточнению пользователя от 26.10.2026 сейчас создавать можно только ADMIN. Общий жизненный цикл пароля относится к аккаунту и не зависит от роли; включение будущих ролей и их полномочий требует отдельного изменения.
- Временный пароль даёт только ограниченную сессию для обязательной смены пароля и выхода. Постоянный пароль пользователь выбирает сам; в разделе безопасности доступна последующая смена с проверкой текущего пароля.
- Смена/сброс атомарно отзывают прежние сессии и незавершённые подтверждения; ключи доступа и история сохраняются. WebAuthn не позволяет обойти обязательную смену.
- Сохраняются политика 6–128 Unicode code points с буквой и цифрой, русские сообщения, CSRF, ограничения попыток и хранение только адаптивных хешей. Пароли передаются владельцу вручную вне приложения, без писем и Telegram.
- Существующие аккаунты сохраняют пароли, логины, ключи и доступ; принудительная смена включается только при явном назначении временного пароля.

## Capabilities

### New Capabilities

- `user-password-lifecycle`: общий для аккаунтов жизненный цикл временного пароля, обязательная и добровольная смена, отзыв доступа и интерфейс управления пользователями.

### Modified Capabilities

- `admin-access`: разрешить действующему ADMIN создавать только ADMIN и назначать временные пароли; согласовать ограниченный вход и добровольные ключи с обязательной сменой.
- `backend-api-contract`: описать новые операции управления пользователями и паролями, ограниченное состояние входа, ошибки и совместимость клиентов.

## Impact

Затронуты backend identity/common/security, аддитивная миграция accounts, OpenAPI и генерируемые типы, frontend входа/безопасности/управления пользователями. Сохраняются слой repo, аудит и механизм auth_version/ADMIN_ACCESS_GENERATION. Заявки, расписание, публикации, очередь и DRAFT оплаты не меняются. Расширяется прежняя граница «создание и сброс только оператором», но публичная регистрация, обычные роли, удаление/отключение пользователей, смена роли и почтовое восстановление не вводятся. Это предложение; реализация и поставка ещё не выполнялись.
