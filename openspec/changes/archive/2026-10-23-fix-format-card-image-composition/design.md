## Context

Мотивация — proposal.md. Вложенный скриншот показывает первую карточку #formats,
а не отдельный портрет #coach, исправленный в frontend 0.4.0.

Проверены локальные исходники 22.10.2026:

- balance.webp (768×402) уже обрезает макушку тренера верхней границей файла;
  individual.webp и hero.webp (1600×900) содержат целые головы в исходном кадре.
- Общий object-fit:cover, размеры format-art 270 px (desktop), 220 px
  (промежуточный размер), 245 px (телефон), центрирование и скругление карточки
  задают дополнительное кадрирование. Изображение в JSX имеет width/height 420×340,
  не соответствующие настоящим пропорциям ресурсов.
- Scroll clip-path скрывает до 12% сверху изображения. Hover/focus увеличивают
  его до 1.045/1.035. Сохранение головы только при прогрессе 100% не решает дефект.
- Прежний тест портрета проверяет #coach; тест форматов проверяет масштаб,
  положение карточки и CSS, но не содержимое исходника или целостность голов.
- Main specs пока нет; public-landing берётся из неархивированных изменений.
  При будущей синхронизации сохранить прежние требования и добавить этот delta.
- Сайт-источник концепции при read-only проверке недоступен; наличие его более
  полного исходника не подтверждено. Приложение собирается из отслеживаемых assets.

## Goals / Non-Goals

**Goals:** устранить обрезку на уровне ресурса и показа, сохранить пропорции,
целые головы и видимый запас во всех режимах, сделать визуальные доказательства
частью приёмки. Проверить все три карточки, включая промежуточные ширины.

**Non-Goals:** изменение backend/API/авторизации, добавление полей контента,
перестройка остальных сцен, смена концепции «Воздух» и повторное исправление #coach.
План не объявляет текущие изображения документальными фотографиями.

## Decisions

### 1. Полный исходник — обязательная часть исправления

При apply сначала проверить источник/локальные материалы на более полный кадр
той же мини-группы. При его отсутствии заменить иллюстрацию мини-группы на
полноценную композицию того же назначения: тренер с детьми, оздоровительная
гимнастика, спокойная светлая палитра, целые головы с запасом. Получение/создание
нового ресурса выполняется в apply с соблюдением применимых правил imagegen,
если используется генерация. Оригиналы info и пользовательского вложения не менять.

Выбранный файл и его происхождение хранить в frontend/public/images и README
ресурсов. Если байты меняются, использовать новое имя файла вместо перезаписи balance.webp:
обычный статический ресурс кэшируется браузером. Новый URL исключает ожидание истечения кеша у старых вкладок.

Один object-position:top или contain для текущего balance.webp отвергнут:
отсутствующие пиксели головы так не восстанавливаются. Простое добавление полей
вокруг уже обрезанного файла также не исправляет композицию.

### 2. Целый кадр внутри адаптивной рамки

Базовый вариант — общая рамка пропорций 16:9 для трёх карточек и contain
на спокойной подложке, с корректными исходными width/height. Фиксированные
высоты 270/220/245 заменить размером от ширины. Небольшие поля допустимы ради
целостности сюжета. Подбор финального исходника может убрать эти поля без crop.

Скругление проверять по реальным головам, особенно у правого тренера «Первого
занятия»; при конфликте уменьшить радиус медиа/верхнего угла карточки или добавить
внутренний отступ. Приоритет — целая голова с видимым запасом, не прежний радиус.
Не ограничиваться проверкой прямоугольника img: скруглённая маска тоже скрывает пиксели.

Альтернатива cover с индивидуальным focal point не выбрана базовой: она зависит
от каждой ширины и не гарантирует сохранность всех участников в групповом кадре.
Схема LandingContent и транспортные DTO остаются прежними; карта локальных ресурсов
и их настоящих размеров — статическая конфигурация frontend, не произвольный CSS.

### 3. Движение без обрезки людей

Сохранить последовательный сдвиг внешних карточек и существующий локальный
scroll-progress; убрать маску, срезающую верх изображения. Реакцию hover/focus
для форматов строить на рамке/подложке/тени и стрелке CTA. Zoom изображения
допустим только при доказанном запасе во всех контрольных состояниях; базовое
исправление использует отклик рамки без zoom, чтобы исключить повторный дефект.
Изображение/сцену hero и #coach не менять. Выявленное матрицей 768 px
переполнение декоративного halo устранить минимальным уменьшением его правого
края: проверка страницы не должна оставлять горизонтальную прокрутку. Прежнее ожидание обязательного scale >1.02 у первой
карточки в тестах заменить проверкой заметного безопасного отклика.

### 4. Приёмка по изображению и состояниям

Сначала сохранить визуальный baseline исходного файла и текущей карточки.
Для каждого нового ресурса проверить целые головы без участия браузера.
Затем снять все три карточки: 320/375/390/430, 768/1024, 1280/1440/1920 px,
с минимум двумя высотами окна на мобильном и desktop-размере.

На 375/390 и 1440 проверить 0/25/50/75/100% и обратные 50%, покой/hover/focus,
переход к якорю и resize. Сохранить снимки и просмотреть лица/макушки/зазор вручную.
Если используется проверка координат защищённых областей голов, зафиксировать их
для выбранных ресурсов; такие проверки дополняют, но не заменяют визуальную приёмку.
`naturalWidth > 0`, contain и правильный aspect-ratio сами по себе недостаточны.

Проверить no-JS, reduced-motion, coarse-pointer/первое касание, CTA гостя и FULL.
Production build, typecheck, форматирование и релевантные browser-регрессии
выполнять на Node 24. Плавность проверить прежним стендом CPU ×4 на 375/1440:
p95 ≤32 ms, ≤1% интервалов >50 ms, без scroll-задач >100 ms и layout на каждом кадре.
Отсутствие обрезки важнее сохранения конкретной маски или масштаба.

## Risks / Trade-offs

- Полного старого исходника может не быть → заменить саму иллюстрацию; не принимать
  CSS-only вариант с видимой, но уже обрезанной головой.
- Contain даёт поля и меньший сюжет в узкой карточке → подбирать композицию 16:9,
  сохранить читаемость лиц и мягкую подложку; не растягивать изображение.
- Возврат к zoom или большому скруглению повторит дефект → проверять промежуточные
  фазы и защищённые области всех участников, включая правые/левые края.
- Прежние browser-тесты требуют scale у форматов → заменить критерий безопасным
  откликом и визуальными доказательствами, сохранив проверку hover у hero.
- Матрица viewport не является физической приёмкой телефона → обозначать эмуляцию
  и отдельно сверить пользовательский мобильный кадр после реализации.

## Migration Plan

На этапе propose создаются только плановые документы. При apply ресурс/стили/
разметка/тесты меняются локально, затем обновляются AGENTS, storyboard и отчёт
проверки. Миграции БД и перезапись published content не нужны.

Если пользователь поручает поставку, собрать новый версионированный frontend
локально, сохранить предыдущий image/hashed assets, выполнить frontend-only rollout
по runbook с проверкой нового изображения и реальных CTA на публичном HTTPS.
Backend 0.3.0, семь аккаунтов/ключи/семьи/записи, MailHog и соседние сайты сохранить.
Для rollback вернуть предыдущий frontend tag и собственный proxy без отката БД;
отметить, что прежний image возвращает известную обрезку мини-группы.
