## Why

Одинаковая заглушка на рабочем и тестовом доменах мешает сразу видеть тестовый
сайт. Нужен отдельно управляемый для каждой зоны режим работ и простой вход для
владельца, когда этот режим включён. Приложение должно открываться в корне
каждого домена: существующий префикс `/lastochka/` не требуется для заглушки.

## What Changes

- Добавить явную конфигурацию режима работ отдельно для production и test. После
  внедрения production остаётся закрытым заглушкой, test открывается обычным сайтом.
- При включённом режиме показывать логотип и текст «Ведутся работы»; три нажатия
  на ласточку открывают форму отдельного четырёхзначного цифрового PIN.
- При выключенном режиме открывать обычные публичные страницы без заглушки и
  дополнительного PIN. Штатная авторизация кабинета и серверные права сохраняются.
- Перенести приложение, его API и ресурсы на корень каждого домена. Старые
  адреса `/lastochka/` должны безопасно переходить на соответствующие новые
  адреса без обхода gate; проверить открытые вкладки и штатные сессии.
- Сохранить пользовательское правило TLS 1.2 без TLS 1.3.
- Защитить короткий PIN от подбора и раскрытия, сохранить изоляцию зон, предусмотреть
  безопасное переключение и откат без изменения БД и других сервисов.
- Проверить обе конфигурации на test; изменение поведения production выполнить
  только после отдельной отмашки на проверенный выпуск.

## Capabilities

### New Capabilities

- `configurable-maintenance-mode`: Независимый режим работ, вход по PIN и
  безопасное переключение между закрытым и обычным публичным режимом.

### Modified Capabilities

При реализации согласовать новое поведение путей с `public-landing` и
`test-preview-deployment`, сохраняя различие между доменами нового VPS и прежним
общим доменом `play-and-say.ru`, а также с требованиями неархивированного delta
`temporary-site-access-gate` в `deploy-isolated-test-and-production`. Этот delta
уже согласован с раздельными режимами зон и PIN; при последующей синхронизации
или архивировании необходимо сохранить защиту production и данных.

## Impact

Затрагиваются frontend, backend, API и их базовые пути, `infra/site-gate`,
конфигурация Nginx, совместимость старых адресов и вкладок, cookies и
эксплуатационная документация. Проверки охватывают оба домена.
Возможны изменения контейнера gate и процедуры поставки; миграции БД и изменение
пользовательских данных не требуются. Фактическое изменение сайта не входит в
эту подготовку и выполняется отдельным применением change.
