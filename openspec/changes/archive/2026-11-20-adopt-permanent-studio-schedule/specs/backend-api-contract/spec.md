## ADDED Requirements

### Requirement: Вывод датированного расписания из рабочего API
Рабочие операции расписания SHALL читать и менять регулярные интервалы без создания конкретных занятий. Устаревший клиент SHALL получать однозначный ответ при попытке создать новое датированное обращение или изменить отдельную дату. Уже завершённый идемпотентный запрос SHALL воспроизводить прежний результат в пределах действующего срока хранения ключа.

#### Scenario: Обращение из старой открытой вкладки
- **WHEN** старая вкладка отправляет новый запрос с конкретной датой или идентификатором занятия
- **THEN** сервер сообщает о необходимости обновить выбор. Ни заявка, ни задание на уведомление, ни занятие при этом не создаются.

#### Scenario: Чтение после перехода
- **WHEN** открываются главная, форма и редактор типовой недели
- **THEN** им не требуется датированный календарный API; чтение и фоновая работа не порождают экземпляров занятий.

## REMOVED Requirements

### Requirement: Контракт индивидуального исправления прошедшего занятия
**Reason**: Рабочее расписание студии состоит из регулярных недельных интервалов.
**Migration**: Перевести пользователей на редактор типовой недели. Удалить датированные экземпляры с сохранением истории заявок по плану миграции.
