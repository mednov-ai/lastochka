## ADDED Requirements

### Requirement: История отключённого канала Telegram

После переключения система SHALL хранить существующие задания и записанные исходы Telegram и показывать историю допущенным сотрудникам с доступом к заявкам. Незавершённое задание SHALL отображаться как остановленное из-за отключения канала с сохранением исходных данных. Создание и отправка новых заданий Telegram, штатный повтор прежних и автоматический перенос прежних заявок во ВКонтакте SHALL быть недоступны.

#### Scenario: Исторические заявки после переключения

- **WHEN** в базе есть доставленное и ожидающее задания Telegram, затем запускается версия с поддержкой ВКонтакте
- **THEN** прежний успешный исход и запись об ожидавшем задании читаются в карточках, ожидавшее задание показано как остановленное, а в оба мессенджера по этим заявкам запросы не отправляются.

#### Scenario: Повтор из старой вкладки

- **WHEN** прежняя страница вызывает повтор Telegram по историческому API
- **THEN** API прекращает операцию с безопасным ответом об отключённом канале без исходящего запроса и без нового задания.

## REMOVED Requirements

### Requirement: Настроенный получатель
**Reason**: Новая доставка настраивается для ВКонтакте.
**Migration**: Получатель ВКонтакте выбирается и проверяется администратором при подключении.

### Requirement: Состав и безопасное отображение сообщения
**Reason**: Уведомление ВКонтакте содержит номер и защищённую ссылку на данные заявки.
**Migration**: Исторические записи Telegram сохраняются, новые сведения сотрудник открывает в карточке.

### Requirement: Устойчивая доставка и повторы
**Reason**: Обработчик отправки Telegram выводится из эксплуатации.
**Migration**: Историческая очередь остаётся доступной для чтения. Новые задания создаются для ВКонтакте и push по настройкам.

### Requirement: Контролируемый повтор и приёмка
**Reason**: Повтор и приёмка актуальны для ВКонтакте.
**Migration**: ВКонтакте обслуживает собственные задания, для истории Telegram доступно чтение.
