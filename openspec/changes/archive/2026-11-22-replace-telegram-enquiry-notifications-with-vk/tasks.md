## 1. Хранение настроек и отключение Telegram

- [x] 1.1 Добавить очередную аддитивную Flyway-миграцию для настроек, проверенного назначения и очереди ВКонтакте. На отдельной PostgreSQL сверить строки заявок, историю Telegram, общий флаг и подписки push и подтвердить, что новое подключение выключено.
- [x] 1.2 Реализовать хранилище ключа ВКонтакте по модели Альфа-Банка и раздельную серверную конфигурацию ключей шифрования. Проверить AES-256-GCM, случайный nonce, чтение по ID, ротацию, отказ с чужим ключом, другой средой и испорченным шифротекстом. Если используется общий код, прогнать тесты совместимости Альфа-Банка.
- [x] 1.3 Отключить создание и обработку заданий Telegram, оставить чтение истории и отклонять попытку включить канал или повторить старую доставку. Интеграционно проверить историю успешных и ожидавших заданий, старую вкладку и отсутствие исходящего запроса даже при наличии старого токена.

## 2. Подключение и доставка ВКонтакте

- [x] 2.1 Добавить клиент VK API для проверки ключа сообщества, списка доступных групповых бесед и отправки сообщения. На имитаторе проверить фильтрацию и пагинацию, групповые идентификаторы, подтверждение отправки, ошибку внутри HTTP 200, лимиты и отсутствие секрета в URL и диагностике.
- [x] 2.2 Добавить административные операции сохранения зашифрованного черновика, выбора беседы, теста, включения после успешной проверки и отключения. Проверить полную ADMIN-сессию, запрет для STAFF и гостя, CSRF, версию, параллельный тест, поздний результат, неудачную замену рабочего подключения и аудит без секретов.
- [x] 2.3 Подключить снимок ВКонтакте и запись задания к транзакции приёма заявки. Проверить оба канала, каждый отдельно, выключенные каналы, недоступность ВКонтакте и повтор публичной команды с тем же ключом.
- [x] 2.4 Реализовать worker, безопасный короткий шаблон и повтор с тем же идентификатором отправки для одного задания. Проверить перезапуск, временные ошибки, неверный ключ, параллельную обработку, потерянный ответ, раздельные идентификаторы сред для общего сообщества, замену токена для той же беседы и остановку очереди после смены беседы.
- [x] 2.5 Добавить чтение статуса ВКонтакте и контролируемый повтор для ADMIN и STAFF с доступом к заявкам. Проверить защиту от параллельной отправки, отказ для принятого задания и чужой беседы, независимость push и совместимость прежних маршрутов. Экспортировать OpenAPI и обновить сгенерированный клиент.

## 3. Админка и карточка

- [x] 3.1 Разместить в «Заявки → Уведомления о заявках» независимые блоки ВКонтакте и браузерного push. В ВКонтакте показать порядок от ввода ключа до явного включения, выбранную беседу перед включением и текущее назначение при замене ключа. В push отделить общий переключатель студии от подписки текущего устройства. Применить `frontend-design` и `web-design-guidelines`. Проверить русские статусы, отсутствие секрета в ответах и browser storage, очистку поля и доступность push для устройства STAFF.
- [x] 3.2 Добавить в карточку независимые статусы ВКонтакте, push и историю Telegram, открыть карточку по ссылке с безопасным возвратом после входа. Проверить права, прямой вызов, заявку вне первой страницы, независимые ошибки и поздний ответ при смене открытой карточки.
- [x] 3.3 Через `playwright-cli` проверить затронутые сценарии на desktop и mobile в Chromium и WebKit. Проверить путь ADMIN с тестом, названием беседы перед включением и сохранением видимого рабочего назначения при замене ключа. Воспроизвести сбой загрузки каждого блока и проверить, что соседний остаётся доступным, а повтор касается только ошибочного. Проверить доступ STAFF, раздельное управление общей настройкой push и текущим устройством, ссылку из уведомления и браузерный push, где он доступен. Сохранить результаты и назвать непроверенные условия.

## 4. Проверка сборки и подготовки к переключению

- [x] 4.1 Прогнать профильные backend/frontend проверки и проверить сборку. На изолированном восстановлении доказать сохранность данных и совместимость выключенного Telegram со старой вкладкой. Проверить подготовленный путь отката, при котором Telegram остаётся выключенным.
- [x] 4.2 Подготовить инструкцию владельцу и оператору. Проверить, что описаны приглашение сообщества, ввод и замена ключа, ввод ключа только в кабинете, независимая настройка push, раздельные ключи и беседы окружений, восстановление и действия при ошибках. Зафиксировать связь с оставшимися проверками уведомлений в `simplify-enquiry-form-with-age-directions` без отметки о фактической доставке до приёмки.
- [ ] 4.3 После отдельного поручения на поставку и реальную приёмку проверить HTTPS test и TLS 1.2. Владелец вводит ключ в кабинете и подтверждает тестовое сообщение в нужной беседе. Одной синтетической заявкой подтвердить ВКонтакте и push, включая закрытую вкладку на поддерживаемом устройстве, и записать результаты и границы проверки без секрета.
