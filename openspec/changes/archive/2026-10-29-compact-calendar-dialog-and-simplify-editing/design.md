## Context

См. `proposal.md` — Why. Основание аудита — пользовательский снимок Safari от27.10.2026 и текущие исходники поставки0.13.0/V15. Пользовательская вкладка с несохранённым вводом не изменялась; браузерная приёмка исправлений ещё не выполнялась.

Подтверждённые причины и дополнительные недостатки:

| Наблюдение | Основание | Решение |
| --- | --- | --- |
| Крестик/Escape не дают понятного выхода | `Panel` передаёт закрытие в `navigate`; dirty-ветка вставляет section с тремя кнопками в начало `.series-form` | Единый сценарий закрытия и отдельное короткое подтверждение |
| После попытки выхода всё смещается | Предупреждение появляется в потоке перед всеми полями | Подтверждение отдельным модальным слоем, рамка редактора остаётся на месте |
| Форма превышает высоту экрана | Боковая панель720px/100dvh, крупный заголовок, интервалы20/24px, все поля/план/история в одном потоке | Более широкое окно, короткие строки, два шага и дополнительные разделы |
| Возраст и причина занимают место без необходимости | Возрастные поля и причина отмены всегда отображаются | Возраст в «Дополнительно», причина при фактической отмене |
| Доступна серия без выбранной группы | `initialInput` сразу включает editing, список может быть пуст; снимок показывает «Выберите группу» и полную форму | Отдельное обязательное состояние выбора/создания группы |
| Сохранение заблокировано до проверки | В подтверждении выхода кнопка disabled при `editing && !plan` | Сохранение самостоятельно запускает нужные проверки |
| Нажатие бывает без результата во время обновления | `navigate` возвращается при busy/uncertain, часть кнопок остаётся активной; в прошлой HTTPS-приёмке сообщение об успехе появилось раньше завершения обновления | У кнопок явные состояние/прогресс; успех после синхронизации формы |
| Длительность расходится с новым запросом | В моделях одиночного редактора/серии исходно50; у серии нативный number без получасового управления | Общий60-минутный default и единый контроллер ±30 |
| Восстановление формы может выглядеть скачком | Данные, baseline, фокус и страницы меняются асинхронно | Проверить поздние ответы/ранний ввод и отделить геометрию окна от состояния формы |

Последняя строка — направление проверки, а не доказанный дополнительный дефект. Форма нового пустого занятия, перенос существующего и уже введённые параметры при переходе к серии требуют разных правил dirty: системные defaults не становятся пользовательской правкой, реальное изменение и перенесённый несохранённый ввод защищаются.

## Goals / Non-Goals

**Goals:**

- Закрытие имеет один предсказуемый результат с сохранением уже записанного черновика и понятным отказом от локального ввода.
- Основная форма помещается на ноутбуке без вертикальной прокрутки; окно/фокус не прыгают при смене состояний.
- Компактность достигается структурой и локальными размерами, с сохранением точных данных, всех дат плана и защиты публикации.

**Non-Goals:**

- Перестройка лендинга, заявок, оплаты, паролей или всей дизайн-системы; эти панели проверяются на регрессии общей оболочки.
- Изменение V15/API/прав ADMIN, округление существующих занятий, обязательная кратность серверной длительности30 или изменение шага начала/переноса сетки15 минут.
- Автопубликация, автоматическое сохранение непроверенного черновика при крестике, обещание поместить200 дат или200% текст на любой телефон без прокрутки.

## Decisions

### 1. Закрытие отделено от сохранения

Один запрос выхода получает намерение: закрыть окно, вернуться к группам или покинуть редактор. Без изменений выполняется сразу. При реальном dirty открывается компактное подтверждение «Выйти без сохранения?» с пояснением «Сохранённый черновик останется. Последний ввод будет потерян» и двумя действиями: «Остаться» и «Выйти». Фокус исходно на «Остаться»; Escape/крестик этого подтверждения возвращают в форму. «Выйти» выполняет исходное намерение ровно один раз, сохраняет серверный черновик, очищает только несохранённый ввод и восстанавливает фокус к инициатору. Повторные Escape не создают новые слои.

Сохранение остаётся в основном редакторе. Альтернатива «сохранить/продолжить/отбросить» в потоке отклонена: она раздувает форму, двусмысленна и оставляет disabled-действие до предпросмотра. Безусловное отбрасывание при крестике отклонено из-за потери введённых данных. Отдельное трёхкнопочное подтверждение также не требуется.

Проверить обработку native cancel/close, программного закрытия при размонтировании и регистрации обработчика: выход/восстановление фокуса выполняются однократно. Закрытие календарного жеста до редактора по-прежнему только отменяет предложение.

### 2. Закрытие при работе с сервером остаётся управляемым

Читающий запрос можно прервать/инвалидировать и закрыть окно. Отправленную запись нельзя представлять отменённой: короткое подтверждение объясняет, что команда продолжает выполняться, и предлагает «Остаться»/«Закрыть окно». Владение изменяющей командой, её исходным payload/key и результатом находится выше жизненного цикла окна. Поздний ответ обновляет календарь/сообщение о результате, но не открывает закрытую форму заново и не переносит фокус.

После10 секунд без результата интерфейс явно показывает «Результат пока неизвестен»; это клиентская граница ожидания, не обещание отмены серверной транзакции. Повтор использует тот же payload/key. Минимальное состояние восстановления конкретной команды сохраняется для этой вкладки и полного ADMIN-контекста до разрешения; при необходимости пережить reload используется sessionStorage только для несекретных параметров расписания/ключа повтора. Его нельзя автоматически воспроизводить при загрузке, показывать другому ADMIN или сохранять после выхода. Для обычного несохранённого ввода нового автоматического хранилища не вводится.

Срок безопасного повтора берётся из действующей политики команд; после его истечения интерфейс требует сверки актуальных данных, а не повторяет запись как новую. Неизвестная команда блокирует новую конкурирующую запись того же редактируемого объекта с объяснением, но не запирает всю студию. Перезагрузка/закрытие вкладки продолжает использовать beforeunload там, где браузер позволяет.

### 3. Устойчивая рамка, короткие основные формы

На desktop от1100px — центрированное окно шириной до1000px и высотой до680px, ограниченное viewport с внешним зазором24px. На меньших экранах окно адаптируется к доступному размеру, на телефоне может занимать экран с safe-area. Верхняя строка, содержимое и нижние действия — три отдельные области; скролл принадлежит только центральной области. Нижние кнопки занимают собственное место и не накрывают поля/фокус. Появление scrollbar не меняет ширину полей.

Тестовые цели без прокрутки для основного шага:1280×800,1440×900 и1522×1230 CSS px при100% текста, без раскрытых дополнительных секций и длинного сообщения ошибки. Проверяются новый одиночный редактор и серия с выбранной группой. На1024×768, коротком viewport, телефоне или200% текста разрешён один вертикальный скролл центральной области; горизонтальный не появляется. Сообщение об ошибке и раскрытие дополнительного раздела могут изменить внутреннюю раскладку, но не положение/размер рамки при неизменном viewport.

Локальные размеры: заголовок22–24px, основной текст14px, подписи13px, вспомогательный текст не менее12px; поля/кнопки на fine-pointer36–40px. Крестик остаётся44×44px. При coarse pointer поля не менее16px, основные цели не менее44×44px. Между подписью и полем сохранить12px и измеряемый зазор до focus outline не менее5px; компактность достигается удалением лишних внешних отступов/пустых строк, а не пересечением подписи контуром.

Не менять глобальный `.button`, шрифты лендинга или масштаб через transform/zoom. Открытие, загрузка, обычные статусы, подтверждение выхода и переход шага не должны менять внешний bounding box более чем на2px при том же viewport; естественная прокрутка к ошибке внутри body допустима.

### 4. Группы и два шага вместо длинного документа

Состояния интерфейса: список групп → короткое создание/редактирование группы → параметры расписания → проверка. Каждое отображает только собственные поля. При переходе от одиночного занятия без группы сначала предложить «Выбрать группу»/«Новая группа», сохранив семя занятия; первую чужую группу автоматически не назначать. Название окна отражает задачу: «Новое занятие», «Изменить занятие», «Расписание группы» с именем группы в отдельной строке; на вложенном шаге достаточно компактного «Назад», без широкой кнопки «К группам и расписаниям».

Пример раскладки параметров серии:

```text
Расписание группы · Ласточки                       ×
Параметры   →   Проверка
Название занятия [................................]
С даты [.......]  По дату [.......]  Начало [.......]
Длительность [−30 | 60 | +30]        Размер [.......]
Дни          Пн  Вт  Ср  Чт  Пт  Сб  Вс
Дополнительно ▸ возраст и сведения
----------------------------------------------------
Сохранить черновик               Проверить расписание
```

Крупный поясняющий абзац заменить коротким «Еженедельно · МСК». Необязательный возраст скрыт в доступном дополнительном разделе; заполненные значения обозначены в его краткой подписи, сохраняются при сворачивании. Группа с ненулевым возрастом не теряет значения по умолчанию. Причина отмены появляется на шаге проверки при реальных отменах или явно выбранной отмене будущей части; ошибка не публикует ничего. История открывается отдельным представлением с возвращением в исходный шаг без потери ввода.

Первый шаг: «Сохранить черновик» и «Проверить расписание». Сохранение не требует предварительно найти отдельную кнопку проверки: при необходимости само выполняет проверки, показывает полевые ошибки, затем сохраняет допустимый серверный черновик. Черновик с конфликтом ресурса допускается, если это допускает существующий API; конфликт отмечается как препятствие публикации. Для публикации обязательно перейти на шаг «Проверка», увидеть актуальный план и отдельно нажать «Опубликовать расписание».

### 5. Полный план остаётся полным

Проверка показывает общий диапазон/количество, добавления/изменения/отмены/сохранённые исключения и конфликты всего плана. Таблица — страницы по10 строк с явным диапазоном строк и общим количеством; при коротком экране разрешена центральная вертикальная прокрутка. Фильтр «Конфликты» и переход к первой конфликтной дате не меняют общий результат проверки. Все200 дат достижимы. Публичная карточка компьютера/телефона открывается переключением отдельного представления;200 полных карточек одновременно не рендерятся.

Альтернатива оставить все строки, карточки и историю под формой отклонена: она делает публикацию визуально оторванной от проверенных данных и не позволяет вместить основной сценарий. При любом изменении правила прежний digest/возможность публикации сбрасываются, ввод остаётся. Возврат к параметрам сохраняет строку/страницу плана, пока правило не изменилось.

### 6. Единый контроллер длительности

Создать общий default60 и одно поведение длительности для одиночного занятия и серии. Кнопки «Уменьшить на30 минут»/«Увеличить на30 минут» и ArrowDown/ArrowUp в поле изменяют значение ровно на30; действия, приводящие к нулю/отрицательному значению, недоступны. Примеры:60→90→60→30;53→83 при явном +30. Нативные стрелки с шагом1 не оставлять конкурирующим управлением. Ручной положительный целый ввод остаётся точным:53 допустимо, step30 не должен породить ошибку кратности.

60 подставляется только при отсутствии заданной длительности: кнопка, плюс дня, клик пустой сетки, новая серия без семени. Выделение интервала18:00–18:45 передаёт45, существующий перенос сохраняет53, серия наследует заданные параметры семени. Шаг выбора начала/переноса/нижнего края сетки15 минут здесь не меняется: пользователь просит добавлять длительность по полчаса, а не округлять все времена.

### 7. Состояния загрузки и фокуса проверяются как часть UX

Фиксировать baseline после получения исходных данных без перезаписи уже введённого текста и без ложного dirty от defaults. Реальное несохранённое изменение, переданное из одиночного редактора в серию, сохраняет защиту. Если редактирование до загрузки опасно, коротко блокировать соответствующие поля с видимым статусом, а не перезаписывать ранний ввод.

Зависимые действия недоступны, пока запись и нужное обновление не завершены; никакой активной кнопки с тихим early return. Обычное уведомление об успехе появляется после согласования формы с ответом/версиями. Чтение нового периода и плана использует защиту от поздних ответов. Начальный фокус не прокручивает заголовок за экран; ошибки переводят фокус только по явной отправке, не при каждой подгрузке. Сохранить нативную модальность, Tab/Shift+Tab, возврат к триггеру и закрытие по Escape верхнего слоя.

## Risks / Trade-offs

- [Слишком мелкая форма] →14px только fine-pointer,16px для touch,44px на важных целях; проверка200% текста и контраста.
- [Обещание отсутствия прокрутки скрывает данные] → измеримые desktop-viewport; доступная вертикальная прокрутка при уменьшении экрана/увеличении текста, полный постраничный план.
- [Новая общая оболочка ломает заявки/оплату] → вариант компактного редактора ограничен календарём; shared close/focus проверяется на всех панелях.
- [Закрытая запись продолжает работать] → запрос не объявляется отменённым; сохранённый payload/key, статус вне окна, безопасное восстановление без автоматического повтора.
- [Шаг30 уничтожает точные значения] → ручной ввод и сохранённая длительность независимы от быстрых кнопок;15-минутные жесты сохраняются.
- [Переходы сбрасывают поля/исключения] → один источник состояния формы, сброс плана только при изменении правила, прежние версии/атомарность API без изменений.

## Migration Plan

1. Реализовать локально и принять сценарий с исходного снимка: пустая группа, недопроверенный ввод, крестик/Escape, короткая форма, возврат и публикация.
2. Проверить существующие50/53-минутные занятия, переход суток, серверные черновики/исключения,200 дат и поздний конфликт; новые значения по умолчанию не записываются в БД при чтении.
3. Пройти production build/typecheck/язык и браузерную матрицу, сохранить измерения/снимки. Код backend/API/схема остаютсяV15.
4. Поставка отдельно после нового поручения: frontend-only, совместимость с backend0.13.0/V15, резервная копия и прежние JS/CSS/сессии. Откат оформления — принятый frontend0.13.0 с тем же backend/V15; это возвращает прежний UX и50-минутный default только для новых форм.
