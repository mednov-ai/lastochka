## 1. Правила расписания

- [x] 1.1 Выявить все серверные маршруты создания и изменения отдельного занятия, черновика, восстановления и серии; составить таблицу разрешённых состояний и проверить её по действующим API и активной дельте.
- [x] 1.2 Реализовать индивидуальное исправление начавшегося/прошедшего неотменённого занятия с сохранением проверки корректности, пересечений, версий и прав; проверить одиночные OPEN/CLOSED/DRAFT, отменённое и будущие занятия серверными сценариями.
- [x] 1.3 Проверить сохранение и повторное открытие черновика, явную публикацию, аудит, прежние снимки заявок и идемпотентный повтор; проверить конфликт версии, ресурса и переход через текущее время без частичных записей.
- [x] 1.4 Реализовать отдельное исправление вхождения серии с сохранением ID, связи, исходной даты и исключения; проверить, что другие вхождения и массовая правка прошедшей части неизменны, а отменённые не восстанавливаются.
- [x] 1.5 Проверить прямые прежние команды, восстановление из истории, неполную ADMIN-сессию, CSRF и конкурентную публикацию; подтвердить сохранность заявок и запрет новой привязки к начавшемуся занятию.
- [x] 1.6 Проверить правило создания новых дат серии с начала текущей недели МСК и публичную доступность после переноса через текущее время; проверить работу при разных часовых поясах и повторной проверке сервером.
- [x] 1.7 При изменении внешнего API обновить серверный OpenAPI штатным экспортом и сгенерировать клиент; проверить обратную совместимость и отсутствие ручных транспортных типов.

## 2. Кабинет

- [x] 2.1 Открывать редактируемые параметры будущих и неотменённых начавшихся/прошедших занятий; для отменённого показывать параметры, название просмотра и причину запрета; проверить оба режима и историю.
- [x] 2.2 Обеспечить выбор только одного прошедшего вхождения, показ старых и новых параметров и предупреждение об изменении доступности заявок; проверить сохранение ввода при ошибках, конфликте, закрытии и переходе к проверке.
- [x] 2.3 Сделать пагинацию пользователей компактной, выровнять номер и сохранить цели не менее 44×44 CSS px; проверить геометрию, крайние страницы, загрузку и переходы клавиатурой.
- [x] 2.4 Перевести создание и редактирование оплаты, включая вход из заявки, в согласованный центральный диалог; проверить поля, ошибки, маску телефона, сохранение и недоступность платёжной ссылки.
- [x] 2.5 Устранить смещение кнопки и символа крестика при наведении, фокусе и нажатии в оплате; проверить отклонение не более 1 CSS px, Escape, возврат фокуса и отсутствие регрессий календарных окон и других панелей.

- [x] 3.3 Проверить сквозные сценарии одиночного и серийного занятия, прошедшей и будущей даты, конкурентных версий, неудачного сохранения оплаты и уже существующих заявок; не использовать реальные данные для тестов.
