## Context

В `AlfaSettings` вкладки используют общую разметку, но отправляют реквизиты в разные маршруты. Для тестовой формы клиент уже проверяет заголовок `X-Lastochka-Alfa-Environment: TEST` и типы полей статуса. Сервер требует обязательный `testConfirmed` при сохранении кандидата и самостоятельно проверяет среду.

## Goals / Non-Goals

Показать наличие сохранённой пары на тестовой вкладке, включая существующие настройки. Изменение ограничено клиентом. Подтверждение боевых реквизитов и выбор шлюза для новых платежей управляются своими действиями.

## Decisions

- В тестовой ветке сохранения передавать существующий `testConfirmed` из проверенного состояния `testKnown` только при явном сохранении новой пары. Параметр URL выбирает вкладку, но сам по себе не подтверждает среду. Удаление флага из контракта потребовало бы согласованного изменения сервера и клиентов. В боевой ветке оставить обязательную галочку и получение `productionConfirmed` из неё.
- При `testKnown && (test.configured || test.candidatePresent)` задать обоим полям `placeholder="••••••••"`. Признак `enabled` описывает доступность подключения и не годится для определения наличия пары. При вводе подсказка исчезает в редактируемом поле. После успешного сохранения и сброса формы она снова видна по актуальному ответу сервера.
- Подставлять точки в значение поля опасно для сохранения через `FormData`. Оставить значения пустыми до ввода и сохранить обязательность обоих полей. Проверка кандидата использует отдельную кнопку и существующий запрос без логина и пароля.
- Сохранить подписи полей. Для сохранённой пары заменить общее приглашение к вводу текстом «Логин и пароль сохранены. Чтобы заменить их, введите оба значения». Связать пояснение с полями через `aria-describedby`. Существующий статус уточняет, прошла ли пара проверку.

## Risks / Trade-offs

- Общая разметка двух вкладок может перенести изменение в боевую форму. Проверка разрешённой боевой вкладки на фикстуре должна подтвердить обязательность её галочки.
- Показ точек до загрузки статуса создаст ложное впечатление о наличии реквизитов. Показывать их только после получения валидного ответа. Первоначальное отображение точек само по себе не должно помечать форму как изменённую.

## Migration Plan

Изменение совместимо с существующим API и сохранёнными парами. Для возврата достаточно предыдущей версии frontend.
