## Context

Мотивация — в `proposal.md`. Пользователь выбрал раскрывающееся меню разделов
в шапке. В текущем Header (`frontend/app/root.tsx`) есть четыре якорные ссылки,
логотип и основное действие; до 1000 px `.header nav` скрывается без замены.
Расписание доступно в подвале. FAQ уже использует `details/summary`.
Локальная проверка исходников не является новой публичной браузерной приёмкой.

Шапка закреплена CSS; `useHeaderOffset` наблюдает её высоту через ResizeObserver
и уточняет положение якорей/фокуса. Модальные вход и панели используют native dialog.
Действующий baseline по отчётам — frontend0.9.5/backend0.9.0/V12.

Дельта `pin-mobile-header-and-relocate-admin-entry` ввела требование
«Постоянная компактная мобильная шапка» с общей высотой до104 px. В настоящей
дельте оно приведено полностью с уточнением закрытого/раскрытого состояний:
размещение третьего действия на320 px требует дополнительного места.
Основное действие, размер текста и целый логотип сохраняются.

## Goals / Non-Goals

**Goals:**

- Одна понятная точка раскрытия мобильной навигации на общих маршрутах.
- Небольшое локальное состояние открытия без библиотеки меню и scroll-listeners.
- Корректные закрытие, фокус и якоря с динамической высотой шапки.

**Non-Goals:**

- Изменение FAQ, сворачивание разделов лендинга или боковая полноэкранная панель.
- Перенос входа администратора из подвала, изменение desktop-навигации и прав.
- Новые API, данные, backend, зависимости, реализация и поставка на этапе propose.

## Decisions

### 1. Обычное раскрытие навигации, без модального слоя

Вынести небольшой компонент мобильной навигации с обычной кнопкой «Меню»,
декоративной иконкой и `aria-expanded`/`aria-controls`. Неподвижные пункты
определить один раз: четыре существующих якоря и `/schedule`; подписи — через
русский каталог. Скрытый список исключать из дерева доступности и Tab посредством
hidden/условного отображения. Не применять role=menu/menuitem: это навигационные
ссылки с обычным Tab, без отдельного управления стрелками.

Список раскрывается на полную ширину внутри потока общей sticky-шапки.
Открытие намеренно увеличивает её высоту; это не overlay и не dialog,
блокировать прокрутку body и запирать фокус не требуется. Для короткого экрана
ограничить высоту раскрытой области по доступной высоте окна, оставить видимый
участок страницы и разрешить вертикальную прокрутку меню. Измерять фактическую
шапку; не задавать её высоту по количеству пунктов.

Без JavaScript дать тот же набор ссылок через нативный `details/summary`
в `noscript` с отдельной строкой переключателя; JS-переключатель в этом режиме
скрыть. Нативное состояние раскрытия предоставляет браузер. Ссылки строить из
того же описания, чтобы подписи и адреса не расходились. Автозакрытие no-JS
после перехода не требуется, но ручное закрытие и видимая цель обязательны.
Это выбранный резервный вариант; полностью JS-зависимая навигация оставила бы
нынешнюю проблему при отключении сценариев.

SSR-кнопка JS-меню до завершения гидратации имеет disabled. Эффект монтирования
включает её после подключения обработчиков; первое доступное нажатие не теряется
на медленной сети. No-JS summary работает нативно независимо от этого состояния.
Сценарии, проверяющие модальный вход, сначала ожидают готовности клиентского
интерфейса: до неё ссылка штатно ведёт на прямую страницу входа.

### 2. Адаптивная компоновка и согласование отступа

На431–1000 px оставить логотип, меню и основное действие одной строкой до104 px;
подбирать ширину логотипа в существующем диапазоне150–195 px по свободному месту.
На320–430 px разрешить две строки до160 px. No-JS с отдельным summary допускает
до160 px на всех мобильных ширинах. При200% текста разрешён дальнейший рост и
перенос, без уменьшения шрифта/областей нажатия и горизонтального переполнения.
Раскрытый список не входит в лимит закрытого состояния. Использовать бирюзовые
токены, безопасные области и видимые контуры; поля версии0.9.5 не затрагиваются.

Не использовать глобальное скрытие всех `.header nav`: разнести desktop/mobile
селекторы. Desktop>1000 px сохраняет прежнюю композицию без мобильного списка.
Существующий ResizeObserver учитывать и после раскрытия/закрытия. Якорный
переход выполнять с учётом уже закрытого меню и нового отступа; проверить
первое открытие главной из другого маршрута и повтор текущего hash.
No-JS использует консервативный CSS-отступ закрытой шапки. Список после
перехода по якорю той же страницы может остаться раскрытым: посетитель закрывает
его переключателем, и браузер сохраняет положение целевого раздела при изменении
высоты. Проверять видимость цели после ручного закрытия реальным касанием/кликом,
а не только URL. Отступ в высоту всего раскрытого меню оставлял бы цель далеко
внизу экрана после закрытия; это уточнено по браузерной проверке apply.

### 3. Закрытие и фокус в соответствии с действием

- Переключатель закрывает/открывает список; ссылка закрывает до перехода,
  включая повтор того же адреса. Закрытие не должно отменять штатный Link.
- Escape внутри меню закрывает его и возвращает фокус к переключателю.
  Нажатие вне шапки закрывает без отмены события и без кражи фокуса/перехода.
- Смена маршрута, desktop-breakpoint и открытие основного действия сбрасывают
  состояние; обратный resize не раскрывает меню заново. Если desktop скрывает
  сфокусированный мобильный элемент, перевести фокус на доступный аналог/логотип.
- При Tab за пределы меню закрывать список после выхода фокуса из шапки,
  сохраняя естественную цель. Закрытые ссылки не участвуют в обходе.
- При навигации не фокусировать исчезнувшую ссылку; сохранить штатное поведение
  маршрута и видимость цели. Dialog выше шапки; закрытие формы возвращает
  фокус к доступному основному действию.

Обработчики pointerdown/keydown и matchMedia подключать только на нужное время,
с cleanup. Не хранить состояние в localStorage и не анимировать высоту через
React на каждом кадре. Переключение панели — непосредственное; небольшой
цветовой отклик кнопки согласуется с текущей темой, reduced-motion без движения.

### 4. Полная карта маршрутов при начальной загрузке

Публичная приёмка выявила воспроизводимое пустое содержимое главной после
клиентского перехода из заявки в WebKit при успешных HTTP-ответах. В trace
наблюдались конкурентные запросы lazy route discovery. Для небольшого набора
маршрутов использовать штатный `routeDiscovery.mode: initial`: карта маршрутов
передаётся с исходным HTML, загрузка кода маршрутов остаётся раздельной.
Это устраняет зависимость навигации меню от фонового обнаружения маршрутов;
подтверждение — повтор исходного публичного сценария и клиентские переходы
между главной, заявкой, расписанием и кабинетом без полной перезагрузки.
Для старых открытых вкладок с lazy discovery сохранить совместимый ответ
`/lastochka/__manifest`:204 с `X-Remix-Reload-Document` и `Cache-Control:no-store`.
Это штатный сигнал клиента React Router загрузить новый документ при обнаружении
маршрута; новые вкладки с полной картой этот endpoint не используют.

## Risks / Trade-offs

- Третье действие не помещается на320 px → предусмотрены две строки и новый
  лимит закрытого состояния; не сохранять старую проверку104 px для узкого экрана.
- Закрытие меняет высоту перед hash-переходом → проверить реальный клик,
  ResizeObserver и положение цели после загрузки, а не только pathname/hash.
- Короткий экран/крупный текст скрывает последние ссылки → ограниченная высота
  с прокруткой и проверки portrait/landscape,200% текста, всех пяти пунктов.
- No-JS и JS расходятся → общий набор пунктов, отдельные браузерные проходы
  раскрытия и навигации обоих вариантов.
- Более ранняя дельта может вернуть старый предел104 px при архивировании →
  сначала синхронизировать/архивировать pin-mobile-header, затем это изменение;
  при архивировании сверить целиком итоговое требование. Сейчас архивы не менять.

## Migration Plan

На отдельном apply использовать vercel-react-best-practices. Внести Header/CSS/
каталог/при необходимости уточнение header-offset и целевые проверки. Основная
матрица: Chromium/WebKit ×en-US/ru-RU ×375/1440 для гостя и ADMIN; дополнительные
320/430/431/768/1000/1001 px, высоты568/844 и landscape,200% текста, no-JS/touch/
reduced-motion. Проверить выбор каждого пункта из главной и другого маршрута,
повтор hash, Escape/outside/Tab, resize, dialog и возврат фокуса.

Выполнить typecheck/build/check:ui-language, форматирование изменённых файлов,
целевую регрессию шапки и форм, строгую проверку OpenSpec. После сборки
перезапустить собственный SSR перед браузерными проверками. Отчёт и статус
обновлять по доказательствам. Поставка — по отдельному поручению независимым
frontend-образом с сохранением backend/V12/данных; откат — на совместимый0.9.5.
