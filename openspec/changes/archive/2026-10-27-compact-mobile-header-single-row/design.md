## Context

Мотивация и согласованное удаление видимой надписи — в `proposal.md`. Сейчас общая шапка использует flex с переносом; правило до 430 px задаёт переключателю `flex-basis: 100%`. Поэтому одна только замена текста иконкой не устраняет вторую строку. Широкий мобильный вариант уже ограничен 104 px, узкий — 160 px.

Есть два представления переключателя: JS-кнопка с отложенной до гидратации активацией и no-JS `details/summary`, сейчас занимающий отдельную строку. Изменение затрагивает оба. Размеры и поведение закреплены в `specs/public-landing/spec.md`. Основные specs и две последовательные активные дельты описывают разные этапы шапки; требуется явно сохранить порядок их синхронизации.

## Goals / Non-Goals

**Goals:**

- Получить одинаковую компактную строку управления при SSR, после гидратации и без JS.
- Обеспечить измеримый результат по геометрии и видимому виду, не зависящий от названия модели телефона.
- Сохранить рабочую навигацию, возврат фокуса и автоматические отступы для закреплённой шапки.

**Non-Goals:**

- Новые ссылки меню, изменение серверного доступа или поведения формы заявки.
- Новая версия изображения логотипа, зависимости или определение устройства по User-Agent.
- Изменение route discovery, совместимости старых вкладок и гидратации, принятых в 0.9.8.
- Деплой и архивирование в ходе подготовки плана.

## Decisions

### 1. Граница одной строки — 375 CSS px

При обычном тексте используем одну строку управления на 375–1000 px независимо от JS; ниже 375 px сохраняем возможность переноса. Это консервативная трактовка запроса об iPhone 11 и более новых телефонах, включающая также компактные окна шириной 375 px. Матрица проверяет ширину viewport, а не соответствие маркетинговому имени устройства.

Альтернатива — снизить существующий breakpoint только до 414 px — оставляет более узкие современные окна в двух строках. Полный запрет переноса вплоть до 320 px и при 200% текста создаёт ненужный конфликт с читаемостью и размерами кнопок.

### 2. Сначала освободить место в элементах управления

В обеих версиях переключателя показывать только встроенную SVG-иконку; доступное имя «Меню» получать из существующего русского каталога, состояние — через `aria-expanded` для кнопки и нативный `details` для no-JS. Иконка крестика заменяет ☰ при раскрытии. Декоративные SVG скрыты от дерева доступности.

Сохранить слово «Записаться» или «Кабинет» и размер не менее 16 px. При необходимости на узкой однострочной ширине убрать только декоративную стрелку основного действия и уменьшить внутренние отступы, сохранив цель нажатия 44×44 px. SVG логотипа не менять; нижняя граница видимой ширины — 150 px. Уменьшение шрифта CTA, обрезание слова или уменьшение кнопки ниже 44 px исключены.

В существующем AuthProvider сессия определяется клиентским запросом. SSR/no-JS даже с ADMIN-cookie показывает публичное «Записаться»; это поведение сохраняется, расширение SSR-авторизации не входит в визуальную правку. Матрица no-JS проверяет обе сессии с прежней публичной подписью, а «Кабинет» — после определения входа в JS.

### 3. Отдельная строка для панели, общая строка для трёх элементов

Пересмотреть узкое правило с полной шириной переключателя и раскладку no-JS `details`, чтобы в закрытом состоянии они не создавали вторую строку. Предпочтительна явная сетка: гибкий столбец бренда с минимумом 150 px, столбец действия по содержимому и столбец переключателя не менее 44 px; интервалы и внешние поля подбираются по доступной ширине. Flex допустим, если выполняется тот же контракт. Визуальный порядок: логотип → основное действие → иконка меню; порядок Tab ему соответствует.

No-JS вариант сохраняет нативные `details/summary`; его summary должен участвовать в общей строке, а раскрытая навигация занимать ширину ниже неё. Конкретное размещение вложенного summary необходимо подтвердить в Chromium и WebKit перед окончательным выбором CSS: потеря нативной семантики или клавиатурного управления недопустима. Дублировать активные переключатели, подменять их скрытым checkbox или требовать JS для компактности не требуется.

Сохраняем safe-area, sticky и `ResizeObserver` измерения высоты. Значения запасного CSS-отступа для JS/no-JS согласовываем с новой закрытой геометрией, проверяя цель якоря до и после закрытия списка. На коротком экране прокручивается список или сама ограниченная по высоте шапка; переключатель остаётся достижимым. При 200% текста допускаем перенос вместо обрезания.

### 4. Приёмка фиксирует строку, а не только максимальную высоту

Расширить существующие проверки без добавления отдельной дублирующей инфраструктуры. Для обычного текста измерять центры трёх элементов (разница не более 2 px), отсутствие пересечения/переполнения, высоту закрытой шапки, ширину логотипа и цели нажатия. Приложить скриншоты: одна только высота до 104 px не доказывает отсутствие двух строк.

Матрица: 320/374/375/390/393/402/414/430/431/440/768/1000/1001/1440 CSS px, Chromium/WebKit, ru-RU/en-US, гость/ADMIN; режимы JS, no-JS, touch/reduced-motion, 200% текста, короткий экран и поворот. Полную геометрическую матрицу выполняем в существующем цикле ширин, специальные взаимодействия — на репрезентативных 375/414/430 px. На 1001/1440 сохраняется desktop-навигация.

Регрессия: все пять ссылок из заявки/расписания/кабинета, повторный якорь, Escape/внешнее нажатие, закрытие при смене маршрута/ширины, форма и её фокус, SSR-кнопка до/после гидратации. Удаление видимого текста не должно менять поиск по доступному имени. Физический телефон отмечается отдельно от эмуляции WebKit.

## Risks / Trade-offs

- [375 px: три элемента могут не поместиться с прежними отступами и стрелкой] → иконка меню, аккуратное уменьшение отступов и удаление только декоративной стрелки; контроль минимальных размеров и видимости полной подписи.
- [Компактная раскладка no-JS может нарушить нативную семантику details] → отдельные проверки доступного имени, состояния, Enter/Space и Tab в обоих движках; не принимать вариант только по скриншоту.
- [Перенос при крупном тексте увеличит высоту] → это разрешённое поведение; измерять новый отступ, достижимость элементов и отсутствие горизонтальной прокрутки.
- [Старые тесты разрешают две строки до 430 px] → заменить допущение проверкой одной строки от 375 px и сохранить проверки остальных свойств.
- [Пересекающиеся активные дельты] → при будущей синхронизации сначала `pin-mobile-header-and-relocate-admin-entry`, затем `add-mobile-header-section-menu`, затем `compact-mobile-header-single-row`; не менять задним числом отчёты принятых поставок.

## Migration Plan

Миграция данных не требуется. После отдельного запуска Apply выполнить frontend-реализацию, целевые проверки и штатные typecheck/build/проверку языка, затем обновить документы как локально реализованные. Номер следующего frontend-релиза выбирается при разрешённой поставке по фактическому состоянию, не фиксируется этим планом.

При отдельном поручении на деплой использовать независимый frontend-образ, проверить текущую стабильную версию и сохранить её для отката. Backend, PostgreSQL, аккаунты, ключи, shared Nginx/TLS и данные сохраняются. Откат — на принятую предшествующую frontend-версию без восстановления БД; прежние JS/CSS и открытые вкладки входят в серверную приёмку.
