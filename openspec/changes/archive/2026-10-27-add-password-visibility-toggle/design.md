## Context

Мотивация — в `proposal.md`. `AuthForm` используется отдельной страницей и окном входа, в том числе для повторного подтверждения пароля. В нём собственный парольный input без переключателя. `PasswordField` уже применяется при смене и назначении пароля: он меняет тип одного input и выводит текстовую кнопку отдельной строкой. `form.reset()` очищает значение, но сам по себе не сбрасывает его React-состояние `visible`.

Действующая дельта `add-user-provisioning-and-temporary-passwords` задаёт очистку секретов и правила временного входа. Дельта `fix-form-focus-label-overlap` требует безопасного расстояния подписи от контура фокуса. Новые требования добавляются в `admin-access`, не заменяя блоки этих изменений. Основная спецификация ещё не содержит всех поставленных дельт; перед будущим архивированием их нужно учитывать.

Дизайн нужен для согласования общего поля, его сброса и поведения до подключения JavaScript между несколькими формами.

## Goals / Non-Goals

**Goals:** единый компонент без копирования логики; сохранение DOM-поля, раннего ввода, каретки, русских ошибок и штатной отправки; управляемое время жизни видимости.

**Non-Goals:** изменения серверной авторизации, политики паролей, данных исходных аккаунтов, API или миграций; восстановление удалённых форм регистрации; установка библиотеки иконок.

## Decisions

### Один PasswordField во всех существующих формах

Расширить существующий компонент только нужными атрибутами и поддержкой сброса, подключить его в `AuthForm`, сохранить назначение `current-password`/`new-password`, имена, ограничения и связи ошибок. Идентификатор поля остаётся устойчивым. Значение хранится в существующем input, а состояние компонента содержит только видимость; отдельного зеркала пароля нет.

Альтернатива — локальный глаз только во входе — оставила бы два разных поведения и дублирование обработки фокуса. Общая переделка всех полей проекта для этой задачи не нужна.

### Глаз внутри поля и семантика обычной кнопки

Обёртка позиционирует кнопку справа по центру input, отдельно от подписи и ошибки; внутренний отступ input резервирует её область. Использовать небольшие встроенные SVG глаза и перечёркнутого глаза с `aria-hidden`, `type="button"`, `aria-controls` и меняющимся русским доступным именем действия с контекстом поля. Имена формируются из общего каталога текстов. Это обычная кнопка действия: отдельная семантика `switch` и противоречащая меняющемуся имени toggle-семантика не требуются.

Область нажатия не меньше 44×44 CSS px; общие отступы подписи и видимый фокус сохраняются. Нативный глаз браузера не считается реализацией требования. Если в поддерживаемом браузере он дублирует собственную кнопку, устранить только такое дублирование в локальных стилях поля, сохранив автозаполнение и менеджеры паролей. Внешняя библиотека иконок избыточна для двух состояний.

### Смена типа без пересоздания input

Менять `type` того же узла между `password` и `text`. Сохранять выделение и каретку; после нажатия указателем из активного input продолжать редактирование там же, без переноса в конец. При клавиатурном переключении сохранять фокус кнопки. Не перехватывать Enter у input: обычная отправка формы остаётся прежней. Переключение не создаёт сетевых запросов, событий отправки или искусственных событий изменения значения.

Альтернатива с двумя input либо новым `key` при переключении может потерять значение, ранний ввод, фокус и связи менеджера паролей.

### Сброс видимости связан со сбросом формы

Компонент возвращает скрытый режим при `reset` своей формы; обработчик подключается и удаляется с жизненным циклом компонента и не заменяет существующий обработчик `RussianForm`. Закрытие и уход очищают/размонтируют формы по действующим правилам; проверить также смену выбранного пользователя в форме назначения. Ошибка отправки не сбрасывает значения или видимость. Не сохранять состояние показа в URL или browser storage и не добавлять в запросы API.

На серверном HTML и первом клиентском рендере пароль скрыт, кнопка отключена. Включать её после подключения обработчиков: первая доступная активация должна работать. Подключение клиента не вызывает `reset` и не заменяет введённое до него значение. Без JavaScript прежние пояснения и ограничения входа сохраняются; новый серверный сценарий авторизации не вводится.

## Risks / Trade-offs

- Смена типа в WebKit может переместить каретку или скрыть клавиатуру → проверить выделение, касание и продолжение ввода в Chromium/WebKit; отдельно обозначить пределы проверки физического iPhone.
- Длинный пароль или штатный значок автозаполнения может пересечь глаз → зарезервировать место и проверить конец строки, оба режима, 320/375/1440 px и 200% текста. Автоматическая проверка заполненного поля не доказывает совместимость со всеми внешними менеджерами паролей.
- После `form.reset()` может остаться открытый режим → отдельный сценарий очистки и повторного открытия для входа, смены и назначения пароля.
- Новый фокусируемый элемент может изменить обход окна входа → проверить Tab/Shift+Tab, Enter/Space, Escape и возврат фокуса на исходную ссылку.
- Рабочий пароль может попасть на снимок проверки → использовать только вымышленные секреты и локальные проверочные аккаунты, не читать приватный файл пароля сайта.

## Migration Plan

1. При реализации применить React skill, выполнить задачи и проверки из `tasks.md`; обновить сведения о локальной готовности после фактического результата.
2. Изменение поставляется отдельной версией frontend с текущим совместимым backend0.11.0/V14; миграция БД, перезапуск backend и изменение аккаунтов не нужны.
3. Пользователь отдельно разрешил деплой. Повторить текущую инвентаризацию и штатные проверки сохранности, проверить backup восстановлением, сохранить прежние ресурсы для открытых вкладок и выполнить frontend-only поставку0.12.1. Откат — только frontend на принятый0.12.0 с тем же backend. При публичной приёмке допустим один отдельный временный ADMIN с последующим адресным удалением; исходные три аккаунта не использовать для смены или сброса пароля.
