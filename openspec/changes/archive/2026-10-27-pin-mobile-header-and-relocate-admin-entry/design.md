## Context

Мотивация — в `proposal.md`. Публичная версия frontend0.9.1/backend0.9.0/V12.
Проверка24.10.2026 на375/390/768/1440 px: position шапки static, после scrollY1000
её верх находится на−1000 px. На375 px высота179,375 px, на768/1440 —176 px.
Доказательства: `artifacts/sticky-header-planning/current.json` и мобильные снимки.

Header и подвал — соседи Outlet в AuthDialogProvider в `frontend/app/root.tsx`.
Ссылка входа уже есть в подвале; гостевой вход в шапке дублирует её. Навигация
скрывается до1000 px, телефон имеет13 px, навигация15 px, мобильная кнопка12–13 px.
У основной кнопки уже есть transition background/transform200 ms; навигация
не имеет согласованного плавного акцента. Требуется улучшить именно шапку.

## Goals / Non-Goals

**Goals:**

- Общая мобильная шапка, закреплённая в потоке документа на всех основных маршрутах.
- Чёткая иерархия для гостя и доступный служебный вход в выбранном пользователем месте.
- Плавные CSS-состояния, которые не вызывают повторных React-render при прокрутке.

**Non-Goals:**

- Новое меню, новое поведение прокрутки, изменение анимаций других блоков,
  перерисовка SVG, закрепление desktop-шапки и обновление backend.
- Хоткеи, тайные жесты, обфускация маршрута, изменение полномочий и защиты входа.
- Реализация и серверная поставка в рамках этапа propose.

## Decisions

### 1. Мобильная шапка через sticky, без скрытия при прокрутке

До1000 px включительно применить position:sticky/top:0 к общему Header с
непрозрачным фоном страницы, тонкой границей/мягкой тенью и отступом
env(safe-area-inset-top). Порог принят по существующему скрытию навигации;
desktop>1000 px сохраняет просторную незакреплённую шапку. Не делать родителем
только hero: шапка должна оставаться доступной вплоть до подвала.

Вместо текущих179 px планируется одна строка «SVG + основное действие» высотой
около80–96 px, максимум104 px без safe area при стандартном тексте. Размер
логотипа адаптировать примерно150–195 px с сохранением обеих надписей; на320 px
сначала уменьшать интервалы и логотип, не шрифт действия. Гостю показывать
«Записаться», вошедшему ADMIN — компактную подпись «Кабинет» прежней ссылки.
На увеличенном тексте разрешить перенос и рост высоты, а не обрезание.

Fixed потребовал бы отдельного заполнителя с риском скачков. JS-скрытие при
движении вниз противоречит постоянной доступности и добавляет ненужное состояние.
Поэтому закрепление не зависит от JS или направления прокрутки.

### 2. Единый отступ для якорей и фокуса

Задать общий CSS-параметр фактической высоты мобильной шапки. При работающем JS
один ResizeObserver у Header обновляет параметр при resize/переносе текста;
не подписываться на каждый scroll и не проводить высоту через React-state.
На desktop отступ закрепления равен0. Для no-JS задать согласованный CSS-отступ
по мобильному варианту и более консервативный отступ при переносе; проверить
прямые hash-переходы, клавишу Tab и200% текста отдельно без JS.

Scroll-padding/scroll-margin использовать согласованно, без двойного сложения
высоты. При изменении высоты после загрузки и прямом hash открыть цель ниже
шапки; корректировать положение только для реальной скрытой цели/фокуса,
не перехватывать произвольную прокрутку посетителя. Сохранить skip-link.

Слои согласовать с существующими календарём, панелями, native dialog и
уведомлениями. Header выше обычного содержимого, но ниже модальных слоёв;
при открытой форме фон и шапка не перехватывают нажатия. Учесть экранную
клавиатуру и динамическую высоту окна на телефоне.

### 3. Вход только в подвале и по прежнему адресу

Пользователь явно выбрал «ссылка в подвале + прямой адрес». Убрать гостевой
AuthLink из Header на всех ширинах. В существующем подвале использовать
«Для администратора» как второстепенную текстовую ссылку: ориентир14 px,
спокойный цвет с читаемым контрастом, область нажатия минимум44 px по высоте,
явный focus-visible. Не использовать opacity, делающую текст нечитаемым.
Это перенос акцента, а не механизм ограничения доступа.

Сохранить AuthLink, модальный вход, его русские ошибки/возврат фокуса и
`/lastochka/auth/login`. Без JS ссылка открывает существующую прямую страницу;
новый сценарий отправки парольной формы без JS в объём не добавляется.
Текст переиспользовать через русский каталог согласно правилам проекта.
Уже вошедшему ADMIN оставить быстрый переход в кабинет в шапке.

### 4. Крупная типографика и согласованный hover/focus

Desktop: навигация18 px, телефон и кнопки16 px. Mobile: кнопки16 px и области
нажатия44×44 px. Не увеличивать шрифт через transform:scale: он меняет
визуальные границы и ухудшает компоновку. Контрольные точки1000/1001 px
проверить отдельно с крупной навигацией и состоянием ADMIN.

Для навигации и телефона применять плавные color/background-color и
декоративную линию через псевдоэлемент с transform/opacity. Для основной
кнопки — более выраженную смену фона/тени и небольшой обратимый translateY.
Ориентир200 ms ease-out, общий допустимый диапазон160–260 ms. Не менять
padding, border-width и font-size на hover. Контраст текста сохраняется и
в промежуточных кадрах. Focus-visible получает тот же акцент и отдельный контур.

Hover-движение включать при hover:hover и pointer:fine. На touch первое касание
сразу активирует действие. При reduced-motion убрать движение/прорисовку и
transition, сохранив мгновенный цветовой акцент и контур. Не добавлять
библиотеку анимации ради CSS-состояний шапки.

## Risks / Trade-offs

- Sticky перестаёт работать из-за overflow/transform предка → проверить всю цепочку
  общего layout и фактическое закрепление в конце страницы, не только computed style.
- Компактность расходится с прежним требованием большей высоты телефона → дельта
  явно заменяет это правило; просторный desktop и целый SVG сохраняются.
- Крупный текст не помещается у порога desktop → согласовать интервалы/переносы,
  проверить1000/1001/1024 px, не уменьшать размер текста ниже требований.
- Шапка закрывает цель, поле или кнопку панели → единая высота/слои и проверки
  hash, Tab, resize, клавиатуры и возврата фокуса на реальном layout.
- Подвал становится труднее найти администратору → сохранить прямой адрес
  для закладки и быстрый кабинет после входа, без обязательного хоткея.

## Migration Plan

Миграций БД и изменений API нет. При отдельном apply использовать
vercel-react-best-practices, изменить общий layout/CSS/каталог и целевые проверки.
Пересмотреть прежние тестовые ожидания ширины195 px/высоты179 px и входа в Header,
сохранив проверки SVG, маршрутов и данных. Проверять production-сборку после
перезапуска собственного SSR, не пересобирать работающий стенд во время прогона.

Матрица: Chromium/WebKit ×en-US/ru-RU ×375/1440 для гостя/ADMIN; геометрия320–1920,
оба края порогов680/1000, высоты568/844, portrait/landscape,200% текста,
no-JS, reduced-motion, touch. Нужны снимки начала/середины/подвала и запись
hover-входа/промежуточного состояния/выхода вместе с проверкой отсутствия layout
сдвигов. После typecheck/build/check:ui-language и целевой регрессии обновить
документы по доказательствам. Сервер обновлять отдельным frontend-образом только
по отдельному поручению; откат возвращает совместимый frontend0.9.1 без изменения V12.
