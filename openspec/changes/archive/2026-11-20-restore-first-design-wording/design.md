## Context

В опубликованной записи могут лежать исходные тексты, значения после V24 или собственная редакция. Главная уже сопоставляет известные варианты при серверной отрисовке. Несколько коротких подписей заданы в шаблоне страницы.

## Goals / Non-Goals

Посетитель получает одинаковый текст при серверном выводе и после загрузки страницы в браузере. В редакторе источником остаётся опубликованная запись. Состав девяти надписей задаёт таблица в proposal.md.

## Decisions

- Отображать штатные варианты заголовков и абзаца первого посещения по точному совпадению всего поля. Проверять заголовок и описание независимо. Массовая замена по фрагменту могла бы исказить авторскую редакцию.
- Подписи оформить обычным текстом в существующих секциях. Подпись расписания разместить в его общей шапке, чтобы она присутствовала при загрузке, ошибке и получении данных.
- Кнопки оставляют действующие названия и цели. Так посетитель, выбравший расписание или запись, попадёт туда, куда указывает подпись.

- Для движения фото, линии раздела и карточек использовать существующий механизм локального прогресса и разрешённые пресеты контента. Положение текста и кнопок первого экрана фиксировано. Открытый ответ FAQ получает короткий переход. На телефоне уменьшить амплитуду, при уменьшенном движении или без JavaScript показать статическое оформление.

### Палитра публичной главной

Первый экран и раздел «Наш подход» получают однотонный фон `#F7FBFA` из первой версии. Разделы стоимости, тренера и контактов чередуют белый и `#F7FBFA`. Убрать зелёный градиент первого экрана. Подложку под фотографией осветлить до бледно-мятной, сохранить тонкую охристую рамку и движение фотографии. Основной текст остаётся тёмным. Фирменная бирюза выделяет логотип, кнопки записи и ссылки.

### Появление расписания и смена недели

При первом попадании готовой таблицы или карточек дней в область просмотра поднять содержимое на 16 CSS px до его обычного положения. Выполнить эффект один раз за открытие главной, в том числе при прямом входе по якорю расписания. Текст и действия доступны с первого кадра.

При смене недели анимировать только область дней. Для более поздней недели начать на 48 CSS px правее конечного положения, для более ранней — на 48 CSS px левее. Длительность перехода составляет 250 мс. Сравнивать даты начала недель при любом способе выбора, включая календарь, кнопку «Текущая неделя» и переход к ближайшему занятию. Выбор даты в уже показанной неделе не запускает перелистывание.

Оставить заголовок и панель управления на месте. Обрабатывать следующий выбор сразу, даже если предыдущий переход или запрос ещё выполняется. Показывать состояние загрузки для последнего выбора и согласованно выводить диапазон дат, дни, занятия и ссылки этой недели. При ошибке использовать существующее сообщение и повтор запроса. Сохранять фокус на использованном элементе управления, положение прокрутки и возможность продолжать ручную прокрутку.

При включённом уменьшении движения показывать готовый результат сразу после получения данных, без обоих эффектов. Без JavaScript сохранять существующее статическое представление раздела и доступ к заявке.

## Risks / Trade-offs

- Редактор может показывать исходное штатное значение, пока страница показывает его публичную формулировку. Это уже действующий порядок для вводного абзаца. Миграция содержимого потребовала бы изменения сохранённых данных.
- Новые строки могут перенестись на узком экране. При приёмке проверить заголовки, переходы и переносы на компьютере и телефоне.
