## Context

Мотивация — в `proposal.md`. Основание: предоставленный пользователем снимок Safari и локальные исходники; текущий публичный сайт в рамках планирования не проверялся инструментально. На снимке подтверждено пустое состояние; заполненная неделя и телефон требуют отдельной проверки при реализации.

`SchedulePeriod` использует общую `.toolbar` с flex-wrap без выравнивания и без отдельной группы даты. Правила поля ограничиваются общим padding и max-width; отступ подписи, предусмотренный для `.form-card`/`.workspace-panel`, на него не распространяется. `schedule.tsx` независимо выводит пустую `.notice` и постоянный `.general-enquiry`; общие `.page h2` добавляют крупные отступы внутри последнего. На снимке не видно обрезания значения даты — это риск для проверки, а не установленный дефект.

Рабочая копия содержит значительные предыдущие изменения. Действуют основные specs и поставленная активная дельта расписания; новая дельта добавляет отдельные требования без переопределения её текста. Дизайн нужен для фиксации неоднозначных решений композиции до реализации.

## Goals / Non-Goals

**Goals:**
- Изолировать оформление расписания от общих форм и административных экранов.
- Сохранить существующую модель недели, запросы, защиту от устаревших ответов и действия карточек.
- Получить проверяемые правила размеров, выравнивания и перестроения панели.

**Non-Goals:**
- Не вводить библиотеку календаря или отдельную модель состояния.
- Не расширять поддержку расписания без JavaScript; существующая серверная подача общей заявки и подбор занятия в её форме сохраняются.

## Decisions

1. **Локальные стили и смысловые группы.** Добавить корневой класс публичного расписания. В панели диапазон расположить над управлением; внутри управления выделить быстрые команды и последовательность «назад — дата — вперёд». На широком экране группы стоят рядом и выровнены по нижней границе контролов. На узком экране идут отдельными строками; при 320 px и увеличении текста допускается дальнейший перенос при сохранении порядка. Альтернатива — менять глобальную `.toolbar` — затронула бы независимые формы.

2. **Нативное поле с полноценной подписью.** Сохранить `type=date`; подпись над полем, отступ 12 px, контролы целевой высоты 48 px, стрелки минимум 44×44 px. Между независимыми областями минимум 12 px, у поля достаточно ширины для нативных сегментов обоих языков браузера. Не фиксировать формат строки даты: им управляет браузер, проверяется полнота отображения. Выравнивание нижних границ не должно зависеть от высоты подписи. Альтернатива — свой календарь — неоправданно расширяет объём и клавиатурную логику.

3. **Пустой период как один завершённый блок.** Только после успешного пустого ответа показать заголовок «На этой неделе пока нет занятий», короткое предложение выбрать другую неделю либо оставить заявку, пояснение «Заявка не резервирует место» и основную бирюзовую кнопку общей заявки. Недельная навигация остаётся доступной над блоком; кнопку следующей недели внутри блока не дублировать. Постоянную плашку помощи скрыть в этом состоянии. Для заполненной недели оставить помощь после карточек/пагинации, с более спокойным оформлением. Для загрузки/ошибки допустима компактная общая заявка без текста об отсутствии занятий. Альтернатива — только поменять padding у двух плашек — сохраняет повтор и слабую иерархию.

4. **Сетка и интервалы без редизайна оболочки.** Сохранить контейнер страницы шириной до 1080 px; основные секции получают общий край. Панели дать внутренние отступы 24 px на широком экране и 16 px на телефоне, между секциями ориентир 24–32 px, между пояснением и кнопкой 16 px. Локально отменить наследуемые большие поля заголовков в блоке помощи. Не фиксировать высоту всей страницы и не подгонять подвал к одному скриншоту. Точные мелкие интервалы можно уточнить при визуальной проверке в рамках указанных требований.

## Risks / Trade-offs

- [Safari по-разному рисует дату] → измерить реальный input и проверить снимки WebKit/en-US/ru-RU; физический Safari/iPhone не объявлять проверенным по эмуляции.
- [Перенос стрелок разрушает связь с датой] → согласованные группы и порядок DOM, отдельная проверка 320 px и текста 200%.
- [Общие стили меняют карточки в других контекстах] → локальный корневой класс, поиск потребителей до правок и регрессия формы выбора/предпросмотра.
- [Пустой экран скрывает дефект запроса] → независимые состояния загрузки, ошибки, успешного пустого и непустого ответа; тест повторной загрузки и быстрых переходов.
- [Автоматические размеры создают ложную уверенность] → визуально просмотреть снимки всех основных состояний; браузерные измерения дополняют просмотр.

## Migration Plan

Миграций данных и API нет. Реализация и приёмка локальные, исключительно frontend. После реализации обновить отчёт со снимками и фактическими результатами; не менять статус поставленной версии. При отдельном поручении на поставку использовать штатный frontend-only процесс и текущий совместимый backend0.11.0/V14; откат — на предыдущий принятый совместимый frontend, без отката БД/backend.


## Implementation findings

При публичной проверке0.11.1 выявлена существовавшая разница ICU: Node/Chromium форматируют «пн», WebKit — «Пн». Первоначальный текст недели расходится при подключении React (ошибка418), хотя дальнейшее управление работает. В SchedulePeriod обе границы приводятся к нижнему регистру без подавления предупреждений. Отдельный сценарий слушает pageerror с первого открытия и проверяет переходы.0.11.1 заменяется исправлением0.11.2; серверный этап этим не считается завершённым до повторной приёмки.
