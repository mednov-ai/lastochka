## Context

Форма постоянного расписания использует общий компонент для создания и изменения правила. API требует положительную вместимость, которая сохраняется в правиле, занятиях и снимках; старые правила могут иметь размер, отличный от 8.

## Goals / Non-Goals

**Goals:** исключить ввод размера из формы и сохранить корректность создания и изменения правила.

**Non-Goals:** удаление данных, миграции, изменение других форм или переопределение сохранённых значений.

## Decisions

Для нового расписания frontend передаёт прежнее внутреннее значение 8, чтобы не менять контракт и поведение существующего backend. При редактировании он передаёт точную сохранённую вместимость правила, а не значение по умолчанию. Поле и связанная с ним доступная ошибка удаляются из формы. В остальных сценариях хранения и отображения значения сохраняются прежние правила.

## Risks / Trade-offs

Внутреннее значение остаётся техническим параметром совместимости; оно не означает доступные места. Ошибочное применение 8 при редактировании изменило бы ранее сохранённые данные, поэтому проверка обязана использовать правило с другим значением. На test и production изменения не выпускаются без отдельного запроса.
