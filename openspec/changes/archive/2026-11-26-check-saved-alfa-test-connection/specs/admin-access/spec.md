## ADDED Requirements

### Requirement: Проверка сохранённого тестового подключения Альфа-Банка

На вкладке «Тестовый шлюз» ADMIN SHALL иметь возможность явно проверить сохранённую версию реквизитов чтением статуса контрольного тестового заказа в банке. Проверка SHALL использовать действующие требования к роли, сессии, подтверждению пароля администратора и CSRF. Сервер SHALL выбирать сохранённую пару самостоятельно. Результат SHALL относиться только к проверенной версии и текущей попытке.

#### Scenario: Повторная проверка сохранённой пары
- **WHEN** тестовая среда подтверждена, сохранена проверенная пара, новой пары для проверки нет и ADMIN нажимает «Проверить подключение»
- **THEN** проверка доступна при пустых полях с точками, сервер сверяет ответ тестового банка с контрольным заказом и при совпадении кабинет показывает «Подключение подтверждено» и время проверки
- **AND** дата изменения реквизитов, выбор шлюза, платежи и состояние подключения сохраняются

#### Scenario: Сохранена новая пара или в форме есть черновик
- **WHEN** помимо проверенной пары сохранена новая пара, ожидающая проверки
- **THEN** «Проверить подключение» использует прежнюю проверенную пару, а «Проверить новые реквизиты» запускает существующую проверку новой пары с возможностью её активации
- **AND** проверка подключения сохраняет введённый черновик и ожидающую проверки пару

#### Scenario: Первое подключение
- **WHEN** проверенной пары ещё нет
- **THEN** кабинет предлагает сохранение введённых реквизитов, а после сохранения кандидата показывает «Проверить новые реквизиты». Действие «Проверить подключение» отсутствует

#### Scenario: Отключён приём новых платежей
- **WHEN** проверенная пара сохранена, приём платежей отключён и сервер разрешает проверку тестового банка
- **THEN** ADMIN может проверить доступ по сохранённой паре. После успешного ответа приём платежей остаётся отключённым

#### Scenario: Недоступный или неподтверждённый результат
- **WHEN** отсутствуют необходимые настройки проверки, банк отклонил запрос, истекло время ожидания или ответ не совпал с контрольным заказом
- **THEN** кабинет показывает результат текущей попытки с доступной причиной. Тайм-аут и неизвестный заказ не обозначаются как неверный пароль. Сервер сохраняет конфигурацию при любом исходе
- **AND** при запрещённой или неизвестной среде, недостаточных правах или отсутствии контрольного заказа сервер не обращается к банку

#### Scenario: Реквизиты сменились во время запроса
- **WHEN** проверенная версия заменилась до получения результата либо ADMIN покинул тестовую вкладку
- **THEN** кабинет не показывает устаревший успех для новой версии или другой вкладки. Повторная проверка запускается только явным действием ADMIN
