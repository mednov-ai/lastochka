## ADDED Requirements

### Requirement: Запрет боевого эквайринга на тестовой площадке
Конфигурация приложения SHALL по умолчанию запрещать боевой шлюз. На тестовой площадке итоговая конфигурация SHALL запрещать боевые реквизиты, сетевые команды и операции через все серверные маршруты и процессы; сервер или проверка поставки SHALL блокировать противоречащий runtime override. Тестирование SHALL использовать отдельные данные и контролируемые заглушки либо тестовый банк, не настоящие боевые реквизиты. При отдельно порученной поставке SHALL проверяться итоговая конфигурация, прямой запрет, сохранность ADMIN и данных, совместимость ресурсов, откат и прежнее правило TLS 1.2. Production требует отдельной отмашки.

#### Scenario: Тестовый стенд с запрещённым боевым шлюзом
- **WHEN** полностью вошедший ADMIN на test открывает боевую вкладку либо напрямую вызывает боевой API
- **THEN** отображается причина недоступности, секреты не принимаются и реальный банковский запрос не отправляется

#### Scenario: Ошибочное разрешение в переменной окружения
- **WHEN** итоговые параметры тестового запуска разрешают боевой шлюз
- **THEN** проверка останавливает запуск либо выпуск и не объявляет стенд безопасным
